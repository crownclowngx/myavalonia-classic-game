# 中国跳棋 Document 设计与开发说明

## 功能边界与规则口径

中国跳棋以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.chinese-checkers`。每次打开 Document 都创建独立棋局；关闭后取消电脑搜索、
停止计时并解除动画输入锁。

首版采用双人对角十子规则。六角星棋盘由中心半径 4 六边形和六个十孔三角营地组成，共 121 孔；蓝方先手，蓝红双方
分别从相对营地出发，最先让自己的十枚棋子全部进入对角目标营者获胜。

- 每回合只移动一枚棋子：走到六方向相邻空孔，或跨过紧邻的一枚任意颜色棋子落到其后对称空孔。
- 连续跳可以改变方向并在任意合法落点结束；单步与跳跃不能混用，被跳棋子不会被吃掉或移动。
- 棋子进入目标营后不能退出；连跳途中第一次进入目标营后，余下路径也必须留在目标营。
- 同一终点可能存在多条连跳路线。规则使用固定六方向顺序 BFS，选择不重复棋位的稳定最短路径。
- 对手进入当前方起始营且营内仍有当前方棋子时，如存在从营内移动到营外的合法着法，本回合只能撤营；若完全没有撤营着法，
  对手因堵塞获胜。

首版支持本地双人和人机对战，玩家可执蓝或执红，并提供简单、中等、困难三级电脑。辅助功能包含合法终点、稳定提示、
决策点撤销、累计计时、局内记录与可关闭动画。不提供 3–6 人、联网、存档、重做、排行榜、AI 对 AI、音效或持久战绩。

## SOLID 职责与朴素设计

```text
Features/ChineseCheckers/
├─ Domain/                 # 121 孔拓扑、纯规则、快照、撤销和三级 AI
├─ ViewModels/             # 模式、异步电脑、计时、提示、记录和动画计划
├─ Views/                  # AXAML、六角星自绘与输入转发
└─ ChineseCheckersDocument.cs
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `ChineseCheckersRules` | 拓扑、完整着法、营地限制、强制撤营与终局 | 历史、线程、计时和 UI |
| `ChineseCheckersGameSnapshot` | 隔离保存 121 孔、回合、终局与最近着法 | 修改真实棋局 |
| `ChineseCheckersGame` | 提交合法事务并保存完整撤销快照 | 模式、电脑和展示文案 |
| `IChineseCheckersMoveStrategy` | 从只读快照选择合法完整回合 | 提交走法或操作 UI |
| `ChineseCheckersViewModel` | 命令、异步电脑、版本隔离、计时、记录和展示投影 | 重复实现跳跃规则 |
| `ChineseCheckersAnimationPlan` | 提供纯视觉时间轴与受限曲线 | 创建计时器或改变棋局 |
| `ChineseCheckersBoardControl` | 绘制、正反坐标命中、动画播放和输入转发 | 判断合法性或胜负 |
| `ChineseCheckersDocument` | Host 标题、ViewModel 所有权和释放 | 游戏规则与命令 |

只对确有三级实现和测试替身的电脑选步使用 Strategy。撤销直接保存不可变快照，不建立 Memento 类层次；状态使用枚举，
不引入事件总线、Mediator、仓储、抽象工厂或跨游戏通用棋盘框架。立方坐标和 BFS 的详细中文注释重点解释设计原因，
直观属性不添加复述代码的空洞注释。

## 坐标、连跳与事务设计思路

立方坐标满足 `X + Y + Z = 0`。中心六边形通过三个分量绝对值不超过 4 生成，再将一个十孔三角形旋转六次组成星角。
像素绘制只把 `(X,Z)` 投影为六角网格点；玩家执红时围绕棋盘中心旋转 180°，领域坐标始终不变。

连跳 BFS 把起点视为已经腾空、当前落点视为被移动棋子占用，其他棋位来自不可变快照。访问集合既阻止无限回环，也保证
首次抵达终点就是稳定最短路径。提交时只接受规则返回的完整 `From/To/Path`，一次复制棋盘并切换回合；非法移动不写棋盘、
步数或撤销栈。

本地双人每次撤销一手。人机模式撤销到玩家上一个决策点：电脑已回应时回退电脑和玩家两手；电脑搜索中先取消搜索再回退
玩家一手；玩家执红且尚未行动时不能撤销电脑初始蓝棋。重新开始、模式/难度/颜色切换、撤销和释放都会增加棋局版本，
旧搜索完成后仍须匹配版本才能提交。

## 电脑、提示、计时与动画

- 简单电脑从全部合法着法随机选择，测试可注入固定随机源。
- 中等电脑使用稳定单层评价，优先进入目标营和强制撤营，再比较目标距离、离营进度与连跳跨度；提示复用此策略且不落子。
- 困难电脑最长思考 5 秒、最多 6 层，使用迭代加深 Minimax/Alpha-Beta、局面缓存和搜索路径循环保护。根节点检查全部着法，
  深层按中等评分只展开前 16 着；预算结束返回最后完成层，测试可注入节点上限。

计时从第一手成功移动开始并包含电脑思考时间，终局停止；撤销终局后继续累计而不倒扣，重新开始才清零。

动画默认开启。路径每段使用 **120ms** 三次减速移动，抵达后追加 **160ms** 轻量脉冲；播放期间锁定输入，完成后才启动
下一回合电脑。关闭动画立即展示已提交快照。重开、撤销、配置变化、DataContext 卸载和 Document 释放都会取消动画。

## UI 与 Plugin 集成

- 自绘控件显示六角星连线、六个营地、蓝红圆棋、最近着法、选择圈、绿色单步点、金色连跳终点和紫色提示路径。
- 人机模式把玩家一方旋转到下方，本地双人固定蓝方在下；命中只改变投影，不修改规则坐标。
- 工具栏提供模式、难度、玩家颜色、重新开始、撤销、提示与动画开关。
- 状态区显示双方目标营进度、手数、当前方、用时、反馈和终局原因，右侧记录本局操作。
- Plugin Module 将中国跳棋追加为第十三个普通 Document；Standalone 第十三个页签复用正式代码。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 拓扑与移动 | 121 孔、对角十子、六方向、单步、跨双方棋子、转向连跳、最短稳定路径、不吃子 |
| 营地与终局 | 目标营只进不出、强制撤营、正常胜利、堵塞胜利和非法零副作用 |
| 状态与撤销 | 快照数组隔离、逐手恢复、终局恢复、决策点撤销和多实例隔离 |
| AI 与提示 | 三级合法性、固定随机、撤营优先、五秒取消、节点预算、输入不变和提示不落子 |
| ViewModel | 双人、人机蓝红方、电脑先行、版本取消、计时、记录与动画锁定 |
| UI/Document | 正反命中、边界拒绝、120ms/160ms 曲线、包装绑定、标题、释放、稳定 ID 和第十三个注册 |

开发阶段只执行：

```powershell
dotnet restore ClassicGamePlugin.slnx
dotnet build ClassicGamePlugin.slnx -c Debug -warnaserror --no-restore
dotnet test tests/ClassicGamePlugin.Tests/ClassicGamePlugin.Tests.csproj -c Debug --no-build --no-restore
```

本功能不使用 AIFLOW，不读取、创建或修改 `.aiflow` 内容。当前不是发布阶段，不增加或运行 Windows CI，不执行 Release
构建、ZIP 打包、Host 部署或发布门禁，也不设置覆盖率发布阈值。

## 手工体验检查

1. 启动 Standalone 第十三个页签，确认 121 孔星盘、双方十子、蓝方先手和浅色/深色文字清晰。
2. 验证单步、跨己方/对方棋子、转向连跳、任意终点停止、目标营锁定和强制撤营反馈。
3. 切换三级人机与玩家蓝红方，确认玩家执红时电脑先行且棋盘旋转。
4. 验证提示只画路径，本地单手撤销、人机决策点撤销和搜索中撤销均恢复正确回合。
5. 开关动画，确认每段移动、抵达脉冲、输入锁定及切换页签后的清理正确。
6. 在真实 Host 打开多个中国跳棋 Document，确认棋局、AI、计时、记录和释放互不影响。

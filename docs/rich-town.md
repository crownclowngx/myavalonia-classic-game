实际证据和继续条件见 [G1 集成记录](plan-history/rich-town/g1-stride-integration.md)与[素材及依赖清单](rich-town-assets-and-dependencies.md)。

## 1. 首要约束与开发范围

1. **SOLID 是首要规定。** 正确性、职责边界和可测试性优先于少写代码；不以性能或演示便利为理由把规则写进 View、渲染循环或 Document。
2. **设计模式朴素使用。** 使用现有 MVVM、组合、窄接口、普通枚举状态机和不可变快照。不建设通用游戏框架、事件总线、Mediator、插件中的插件或庞大的继承体系。
3. **新增和修改的注释使用详细中文。** 解释设计思路、职责、输入约束、线程、所有权、取消和失败路径；不要只翻译方法名或逐行复述代码。
4. **单元测试和本地开发门禁必须齐全。** 测试真实规则与可观察结果；成功路径、边界、失败、并发竞争和释放均有覆盖。窗口与 GPU 验证不能由单测或截图替代。
5. **实现、测试与文档同阶段更新。** 专用文档、索引、进度和实际验证证据同时维护；不把待实现设计写成现状。
6. **不使用 AIFLOW。** 不读取、不修改其内容，不调用其脚本或工作流。
7. **当前不是发布阶段。** 不新增或运行 Windows CI、Windows Smoke/Release Acceptance、Release 构建、正式 ZIP 打包、发布门禁、上传、签名或 tag。
8. **不调用当前统一 `verify` / `seal` 或退役 G8/G10 脚本。** 这些入口包含不属于本任务的构建、打包或封板动作；不得用“本地运行”规避本条。
9. G1 及以后允许使用 **Debug 临时插件目录和隔离的开发 Host** 验证加载、Dock 和资源；这是必要的本地集成检查，不是 Windows CI 或发布门禁。禁止覆盖用户日常 Host 的插件和数据。
10. G0 仅编写文档；用户随后明确要求创建分支并实施，G1 起按本方案实施代码、素材、锁文件和本地开发检查。
11. **一个游戏就是一个独立子领域。** 小镇只使用 `Features/RichTown` 和自己的私有渲染项目，不复用或反向调用其他游戏的领域、ViewModel、状态、随机源或动画服务；只有插件组合根登记多个游戏。

未来真正发布时，再由单独的发布任务启用当时有效的发布流程。本方案不能授予提前执行发布流程的权限。

## 3. 第一版产品与规则

显示名称暂定“富翁小镇 3D”，采用独立地图、地块名和美术表现。入口位于现有“经典游戏”组。
首版 Windows x64、离线单机，默认一名真人和两名电脑；暂不实现联网、多人热座、股票、抵押、拍卖、玩家交易、
复杂道具、地图编辑器、骨骼角色、物理骰子或独占全屏。

### 3.1 地图与经济参数

以下是首版可实施的规则基线，不是已验证的平衡性；数值集中在只读配置中，试玩修改须同步规则测试及本文件。

| 项目 | 规则 |
| --- | --- |
| 地图 | 24 格环形地图，索引 0–23；0 为起点，6/18 为机会，12 为税费，3/15 为休息，其余 18 格为地产 |
| 初始状态 | 三名玩家均在起点，现金 1,500，未持有地产；轮流行动，首名真人先手 |
| 骰子 | 单颗六面骰，每次合法掷骰产生 1–6；没有连掷或额外回合 |
| 起点 | 正常前进跨越或恰好停到起点，发放 200 一次；初始放置不发放 |
| 地产价格 | 地块索引小于 8 为 100，小于 16 为 150，其余为 200；只对地产格应用 |
| 租金 | 设原价为 P，空地为 P/5，一级房为 P/2，二级房为 P；停在本人地产不收费 |
| 购买 | 停在无主地产可按 P 购买或放弃；购买不允许欠款，放弃后不拍卖 |
| 升级 | 结算完成后可升级名下任意一块地产一级，最多二级；每次费用 P，每回合最多一次 |
| 出售 | 可将整块地产连同建筑卖回银行，所得 `(P + 已付升级成本) / 2`，归属和等级同时清空 |
| 税费 | 停到税费格向银行支付 100；休息格无额外效果 |
| 机会 | 四种等概率事件：银行奖励 100、银行奖励 200、缴费 100、缴费 200；首版没有传送、连锁事件或道具 |
| 债务 | 资金不足时进入待偿债状态，只允许出售本人资产偿债；电脑也只能提出偿债出售，不可掷骰、升级或结束回合 |
| 破产 | 现金加全部折价资产仍不足时，自动清算；现金和清算款最多支付到欠款额，剩余欠款免除，地产回到银行，玩家出局 |
| 终局 | 仅剩一人立即获胜；或完成 30 轮后按现金＋地产购买成本＋已付升级成本排名，同分并列 |

一轮指轮次开始时仍在场的玩家各获得一个回合；中途出局者跳过，其余玩家不重复行动。
租金债权人为地产所有者，税费和机会缴费债权人为银行；待偿债只保存一笔确定债务，最终扣款/入账一次。
G2 明确出售仅在“等待偿债”或“回合操作”阶段开放；购买/放弃决定前不能先出售。出售已升级地产不恢复本回合升级额度。
现金、金额和地块索引使用整数并做范围校验；不得用浮点数计算金额，不得在余额不足时先扣成负数再事后补偿。

### 3.2 状态、电脑与动画的关系

领域阶段使用简单枚举：等待掷骰、等待购买决定、等待偿债、回合操作、游戏结束。玩家、阶段和版本共同决定命令是否合法。
每个合法命令由唯一会话串行处理，原子产生新快照和有序领域事件。非法命令不改变金额、随机数、版本或事件序号。
掷骰时完成位置与落点规则推导；动画只回放事件中的路径和结果，不再执行规则。购买和偿债等决策发生在相应领域阶段。

动画期间 UI 暂时锁定相关操作；完成通知只解除展示锁，不执行收租或移动。跳过动画直接显示已提交快照。
重复点击、旧动画回调和重开前的异步结果必须按会话代数、版本和请求身份拒绝；不以一把全局锁管理所有游戏。

电脑先采用一个普通决策器：购买/升级后至少保留 300 现金，升级选择索引最小的可升级地产；不足偿债时按折价金额从低到高出售，
同价按索引排序，能还款即停止。电脑读取快照并提出与真人相同的命令，不直接写现金或提前窥视骰子。
首版无需异步搜索或多档 AI；思考延迟由可控时间驱动，与随机规则分离。

G2 使用 `SplitMix64-v1`，快照保存算法版本和当前 64 位内部状态；仅保存种子不够。
采用拒绝取样消除取模偏差；固定向量、低端样本重试、1–6 边界及恢复续序都有测试。
随机运算是显式输入/输出状态的纯函数，没有环境随机效果，因此没有为它添加接口或测试替身；来源和许可见 G2 专项记录。

## 4. SOLID 职责划分与朴素设计思路

以下名称可随实施调整，职责不可合并成万能 ViewModel 或引擎服务。

| 组件 | 单一职责 | 禁止承担 |
| --- | --- | --- |
| `RichTownRules` / 配置 / 快照 | 校验和计算回合、地块、金额、债务、胜负 | Avalonia、Stride、文件、定时器 |
| `RichTownSession` | 独占对局状态，串行提交、版本检查、原子返回事件 | 创建 HWND、绘制和操作 Host |
| `RichTownComputerPlayer` | 从只读状态提出合法决策 | 绕过规则写状态、播放动画 |
| 可恢复随机源 | 有界取样和状态导出/恢复 | UI、系统时钟、全局共享状态 |
| 存档编解码器 | DTO 校验、序列化和恢复前构造完整快照 | 写 Host 文件、保存 GPU 对象 |
| `RichTownPlayController` / `RichTownPlayback` / `RichTownPresentation` | 会话代数、页面命令、电脑节奏、可控时间回放、中文展示与画面投影 | 经济公式、3D 资源创建、窗口重挂 |
| `RichTownDocument` | SDK 激活、拥有展示控制器及最终释放；持久化/工作台命令在 G4 实现 | 游戏规则、资源搜索、渲染循环 |
| `IRichTownSurface` / `IRichTownPlayableSurface` | 原生表面及画面 DTO、镜头、帧循环的窄边界 | 收租、购买、调用 Host 内部服务 |
| `RichTownViewport` | Avalonia 原生控件与表面生命周期适配 | 对局规则、存档和资产导入 |
| 原生/内容路径适配器 | 显式根目录、依赖注册和错误诊断 | 修改进程工作目录、扫描其他插件 |

SOLID 审查必须逐条回答：

- **S：单一职责。** 修改租金不能要求改渲染器；更换视口不能要求改存档规则；资源路径不能散落在 ViewModel。
- **O：开闭原则。** 同一套规则通过数据表达地块和价格。仅在第二种真实策略出现时引入策略接口，不为未来猜测创建几十个子类。
- **L：里氏替换。** 假视口与真实实现保持输入、顺序、取消和幂等释放契约；G2 随机采用真实纯函数，不靠测试替身吞异常制造通过。
- **I：接口隔离。** 渲染、随机、时间和存档边界只暴露调用方需要的方法；不设计 `IGameService` 式万能接口。
- **D：依赖倒置。** 规则不依赖 UI/引擎；G2 随机状态由快照显式传入且不需要时间服务；未来时间等外部效果通过窄边界注入，组合放在插件注册边界，不使用 Service Locator。

只使用必要的接口：外部效果或需要替换测试的边界才抽象，确定的纯计算使用普通类/函数。
领域事件使用简单不可变记录和有序集合，仅在当前对局传递；它不是事件总线、事件溯源数据库或跨插件消息协议。

### 4.1 项目边界

保持同一个 Plugin ID 和同一套入口。G1 已新增 `Features/RichTown/` 放置小镇 Document、检查页面和私有部署声明。
新增 `src/ClassicGamePlugin.RichTown.Stride/` 专供小镇；没有通用 Stride 服务，也不是第二个插件或可执行游戏。
Plugin 单向引用此项目，后者不引用 Plugin、SDK、Dock 或其他游戏。原生表面边界 `IRichTownSurface` 不暴露 Stride 类型，
G1 没有添加 Contracts 项目。后续领域与会话只放入小镇子领域，领域规则不得使用 Stride/Avalonia。
Stride 构建处理器会随引用传递到消费项目，当前拆分隔离的是源代码职责，不宣称已经隔离全部构建处理。

Standalone 只承载真实 View/Document 和开发期 SDK Stub，不复制规则、资源加载器或贡献清单。
插件组合契约仍由 `ClassicGamePlugin.Tests` 验证；小镇测试放在独立 `ClassicGamePlugin.RichTown.Tests`，不依赖其他游戏测试工具。
真实 GPU 游戏通过 Standalone 的 `--rich-town-play` 显式打开；`--rich-town-probe` 保留独立的 G1 诊断 View，二者共用底层适配器。
游戏默认不进入原有十四个标签页；无窗口单测不初始化 GPU，显式窗口检查见 G3 专项文档。
不引入 Dock 依赖，不引用 Host 内部项目，不将 Stride 类型暴露到公共 Plugin SDK。

### 4.2 中文注释要求

公开及关键内部类型写中文职责说明；状态转换、租金/清算算法、随机恢复、保存修订、HWND/设备次序和跨线程方法写中文设计说明。
必须交代参数单位（DIP/像素/毫秒/格子）、有效范围、返回值语义、调用线程、资源所有者、失败后状态及重复调用约定。
复杂实现旁解释“为何这样设计”和被维护的不变量；注释与实际行为同步，不能留下与代码相反的旧说明。

示例规范：表面解绑方法应说明“这里只撤销当前表面，保留对局；先停止提交 GPU 帧，再由 UI 线程销毁 HWND；迟到帧按表面代数丢弃”。
审查不按注释行数打分，不给自动属性和显而易见的赋值堆砌无意义注释。

## 5. 3D 表现、嵌入与生命周期

### 5.1 视觉范围与素材

默认斜俯视棋盘，左/中侧为 3D，右侧玩家与地产详情，底部操作区。小窗口切换上下布局，不压缩到按钮无法操作。
鼠标拖动旋转、滚轮缩放、按钮复位镜头；顶层窗口激活且鼠标位于视口时响应，不注册键盘钩子或全局快捷键。
小汽车沿格点路径前进；一级显示一栋房、二级显示两栋；车顶点数及地产归属点数与颜色共同识别玩家。
棋盘、地块、边框和骰子程序生成；骰子动画朝向必须与规则结果一致，不启用物理模拟。

| 候选素材 | 用途 | 来源页面 |
| --- | --- | --- |
| Kenney City Kit (Suburban) | 少量住宅与两级建筑 | [素材页](https://kenney.nl/assets/city-kit-suburban) |
| Kenney City Kit (Roads) | 道路与少量中央小镇装饰 | [素材页](https://kenney.nl/assets/city-kit-roads) |
| Kenney Car Kit | 三种可区分的小汽车棋子 | [素材页](https://kenney.nl/assets/car-kit) |

上述页面在方案调研时标注免费、CC0；下载时再次保留实际包内许可。G1 只导入一栋房屋验证格式、材质、比例、轴向与法线；
G3 继续使用同一房屋，汽车、骰子、树木与棋盘程序生成；未引入 Roads/Car Kit 或其他新下载。保留来源 URL、包版本/下载日期、原文件 SHA-256、许可和修改记录，许可证随插件资源交付。
模型导入、纹理转换在构建期完成；用户机器不安装编辑器/资产编译工具、不运行在线下载。源码资产和编译缓存分开管理。

### 5.2 首选集成与技术停止条件

首选 Windows x64、Direct3D 11、Avalonia `NativeControlHost` 承载 Stride 原生子窗口。
具体 GameContext/窗口后端、消息泵、渲染线程和窗口创建线程在 G1 用稳定版本验证，不假设任意 HWND 都能直接传入 Stride。
不能在 UI 线程调用阻塞式游戏主循环。Stride 对象由选定的渲染线程拥有，Avalonia 对象仅在 UI 线程访问，
G3 实际采用 UI 线程外部 Tick：会话、单段回放和 Stride 帧顺序执行，视口只保留最新不可变画面，无后台任务或跨线程队列。

原生视口有叠层限制：页面按钮布置在视口外，但仍须验证 Host 弹窗、命令面板、Dock 拖放提示和浮动窗口。
只在 Standalone 看见画面不算 G1 通过。原方案要求 G1 通过再接入玩法；用户后续明确要求先实施 G3，现将本地可玩开发与集成验收分开。
叠层失败记录保留，仍须评估 GPU 共享纹理、现有公开 SDK 可用的协调能力或单独的 Host 改进方案。
不以修改 Host 私有对象、隐藏所有弹窗、每帧 CPU 截屏复制或改为外部游戏窗口静默替代约定的嵌入目标。

### 5.3 所有权与失效处理

Document Scope 拥有会话、取消源和视口会话租约；View 拥有当前原生表面。表面脱离不等于对局关闭。
首版限制同时运行一个富翁 3D 会话，插件内使用原子租约防止竞争；再次打开显示明确提示，不创建第二个 GPU 实例。
该租约不限制其他十四个游戏。恢复或初始化失败必须释放租约；多实例 GPU 支持是后续任务，不写成首版既有能力。

| 场景 | 要求 |
| --- | --- |
| 首次打开 | 懒加载 Stride，验证资源后创建视口；初始化失败显示可诊断错误，不破坏其他游戏登记 |
| 切换标签/最小化 | 停止不可见渲染和 AI 推进，冻结动画；再次可见后明确继续，不追赶隐藏墙钟时间 |
| 浮动/重新停靠 | 旧表面停止提交并解绑后才绑定新表面；保留规则状态，不重新掷骰或收租 |
| 零尺寸/高 DPI | 区分 DIP 与像素，零尺寸不创建无效交换链；拖动缩放合并设备尺寸更新 |
| 重开 | 取消旧动画/AI，提升会话代数；迟到结果不能修改新对局 |
| 关闭 | 禁止新命令，取消工作，按选定后端顺序停止帧与消息泵、释放 GPU/窗口及订阅，最后归还租约 |
| 初始化中关闭 | 不等待 UI 线程上的阻塞 Join；按阶段清理已创建资源，不发布迟到的视口 |
| 设备丢失/异常 | 暂停会话并展示原因，最多显式重建呈现；重建使用已提交快照，不能重做领域事件 |

设计不能依赖 UI 线程阻塞等待一个还需要 UI 回调的渲染线程。G1 检查 Host 当前关闭契约，确保清理完成前不会访问已销毁 HWND；
若缺少可靠的异步停止边界，必须记为阻塞问题，不能写一个未等待的 DisposeAsync 假装完成。
插件 ALC 当前不可回收；“关闭无泄漏”指每对局线程、窗口、订阅和 GPU 资源回收，不要求运行时卸载所有引擎 DLL。
原生崩溃仍可能影响同进程 Host，不能宣称 ALC 提供进程级故障隔离。

## 6. 存档与工作台契约

拟定 Document ID：`myavalonia.plugin.classic.game.document.rich-town`；
拟定 Restart Command ID：`myavalonia.plugin.classic.game.command.rich-town.restart`。
发布前稳定 ID 以实施记录确认；实现前不修改现有数量断言。仅新增重新开始的工作台命令，掷骰、购买、升级、出售、结束回合为页面操作，
不登记默认全局快捷键、不实现跨随机决策 Undo。Restart 在忙碌时仍走同一取消/重开路径，命令状态变化才通知 Host，不逐帧通知。

存档使用既有 `IPersistablePluginDocument` 和 Host 修订快照/确认契约，不直接在 UI 中另写文件保存器。
内容 schema 初始为 1，与 Host 信封、布局、SDK 和插件版本分开。拟保存：地图/规则版本、玩家与顺序、现金、位置、地产归属等级、
当前阶段、待购买或待偿债内容、轮次、游戏结束结果、随机算法和状态、逻辑修订。可选镜头偏好与领域状态分开。
不保存 GPU 句柄、线程、定时器、控件、Stride Entity、动画中间帧或任务引用。

首版保存只在无活动动画/AI 的稳定边界开放，等待购买和等待偿债也是合法稳定阶段。
隐藏时可显式跳过展示到已提交快照后保存，不再次结算。若 Host 仍请求忙碌会话保存，按公开契约返回可解释结果，不序列化半截状态。
G4 核对真实 SDK 关闭/保存行为；不得杜撰 SDK 方法或在无法表达时绕过 Host。
恢复时先完整校验再替换会话：支持的 schema、地图版本、玩家身份、位置/金额范围、唯一归属、建筑等级、债权、阶段一致性和随机状态。
坏存档不部分覆盖当前对局。旧修订保存完成不能把新修订标成干净；新建、恢复、关闭取消分别测试。

## 7. 插件依赖尽量自包含

目标：正常安装插件后不额外安装 Stride、不联网取资源；私有引擎和原生依赖位于经典游戏插件目录。
这是“插件依赖自包含”，不是另带一个 CLR 的 .NET 可执行程序自包含。运行时由 Host 提供；Windows 图形组件与显卡驱动由系统提供。
VC++ 运行库优先验证许可允许的本地携带方案；插件子目录的加载与原生二级依赖必须实测，不能预先承诺完全免安装。

```text
Controls/ClassicGamePlugin/            # 目标布局示意，并非当前已有产物
├─ plugin.manifest.json               # Build 生成
├─ plugin.build.json
├─ ClassicGamePlugin.Plugin.dll
├─ ClassicGamePlugin.Plugin.deps.json
├─ ClassicGamePlugin.RichTown.Stride.dll # 小镇私有渲染类库
├─ Stride.*.dll / 必要私有依赖
├─ runtimes/win-x64/native/
├─ Assets/RichTown/                    # 编译内容数据库和必要运行资产
└─ Licenses/
```

实施规则：

1. 所有 Stride 包精确同版；盘点 `project.assets.json`、锁文件、生成 targets 和运行时实际加载模块，不手写猜测 DLL 清单。
2. 提供运行时文件的直接/传递 NuGet 包均按 Build 协议显式声明 `ManagedPluginPrivatePackage`；不能认为声明顶层包会自动携带整个闭包。
3. 私有 ProjectReference 输出、生成的内容数据库、许可证和非标准资产使用 `ManagedPluginAsset` 或目录资产显式加入；验证入口 `.deps.json` 与目标路径一致。
4. `Assets/RichTown` 只是插件内物理目录，必须显式接入 Stride 的 ContentManager/数据库或文件提供器，不能假设任意目录会自动成为内容根。
5. 根目录由插件自身程序集位置推导，不使用宿主 `AppContext.BaseDirectory` 代替；检查 Stride 自定义加载路径和可选显式注册。
6. 验证 P/Invoke 和原生 DLL 导入表二级依赖。不修改全局 PATH、工作目录或无限扩大 DLL 搜索范围；必要的平台加载适配保持插件私有、路径明确。
7. 不重复携带 Host 共享的 Avalonia、Dock、SDK 和约定共享库；不得为解决冲突把 Stride 加入 Host 全局共享表。
8. 模型导入工具只供构建；音频、物理、视频、VR 未使用不主动启用，但不凭“没调用”删掉传递依赖。渲染与着色器实际需要的组件以运行验证为准。
9. 缓存和日志写用户数据/临时目录，不要求安装目录可写；资源读取支持中文、空格和只读插件目录。
10. 原生模块与进程级缓存可能驻留到 Host 退出；每局关闭不能调用全局卸载破坏仍有引用的资源。

G1 生成初始依赖清单，G5 固定必要文件、RID、来源、许可证、摘要和实际加载路径。
开发期只检查 Build 协议生成的 **Debug 暂存目录**，不手工复制整个 bin，也不生成正式 ZIP。
没有在干净离线环境验证的依赖必须标为“待验证”，不能用开发机已有 VC++、NuGet 缓存或安装过的引擎作为自包含证据。

## 10. 本地开发门禁与证据

以下命令在经典游戏插件仓库根执行；本轮已经进入代码阶段。推荐使用专用脚本，保留全量测试、TRX 和覆盖率证据。

```powershell
dotnet build ClassicGamePlugin.slnx -c Debug --no-restore -warnaserror -p:SkipPluginDeploy=true
pwsh -NoProfile -File scripts/Test-RichTownDevelopment.ps1
```

省略号必须换成真实文件列表。脚本应逐命令检查退出码，任何一步失败立即停止。

`scripts/Test-RichTownDevelopment.ps1` 已实现，只接受 Debug，不部署或启动窗口，不转调统一 Gate。
默认把证据写到 G3 新目录；`-Phase` 只选择 G1/G2/G3 证据目录，不降低当前检查范围。额外生成 `simulation.json`、`rules-coverage.json` 和 `presentation-coverage.json`，
检查 0–999 全部种子、每局最多 2,000 条命令、恢复续局证据和八个关键类型的覆盖率；报告缺失、零测试、失败或跳过都失败。

这不是跳过测试：其余既有用例、该单例、小镇专用用例均必须通过，TRX 必须无跳过，单例数量必须精确为 1。
直接将全部既有测试混在一个进程仍可能触发旧用例的线程竞争，此限制见 G1 记录。
真实视口集成检查使用显式单独步骤，便于无 GPU 环境运行规则测试；缺 GPU 应报告该项未执行，不得将它算作整个 G1/G5 通过。

该入口不是 Windows CI，不启动 Host、不部署、不授予发布资格；详细断言和人工补充步骤见 G3 专项记录。

进程内存和可取得的 GPU 资源/显存指标。资源缓存不要求每次完全归零，但持续增长、存活的会话线程/窗口或迟到回调必须解释并修复。

- 本文件：当前规则、最终职责、选定后端、内容路径、依赖策略、已知限制和下一阶段前置条件。
- [专项开发记录](plan-history/rich-town/g0-design-and-development-plan.md)：阶段复选框、实际证据、失败原因、设计变更与未验证事项。
- [根说明](../README.md) 与 [文档索引](README.md)：区分可玩游戏、已登记的原型和后续计划，数量及使用说明反映实际代码。
- [项目职责](project-and-window-responsibilities.md)：若新增私有类库或改变释放所有权，更新实际项目分工。
- [工作台命令](workbench-commands.md)：G4 落地时更新 Restart、实际计数和路由事实。
- [部署说明](deployment-and-release.md)：G1/G5 更新实际依赖清单、Debug 暂存方式与限制，不提前启动发布流程。
- 资产来源/许可清单：G1/G3 导入资源时创建，未下载素材不能预填摘要或许可文件名。

完成整个计划需要可玩的游戏、完整单测、本地窗口与依赖验证和如实文档；只有漂亮截图、Standalone 成功或单测通过均不足以宣称全部完成。

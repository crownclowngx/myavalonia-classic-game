## 3. 全程必须维持的边界

1. **SOLID 优先。** 规则算钱和回合，会话控制提交，渲染呈现结果，Document 适配 SDK；不把这些职责合并到一个 ViewModel。
2. **一个游戏一个子领域。** 小镇只使用自己的规则、随机源、电脑、动画、存档和渲染边界；其他游戏不得反向引用小镇。插件组合根可以登记各游戏，但不共享运行状态。
3. **朴素设计。** 纯计算用普通类/函数，有真实替换需求才引入窄接口；不增加通用游戏框架、事件总线或复杂设计模式。
4. **中文详细注释。** 说明设计理由、输入单位、线程、所有权、取消、失败后状态与幂等约定，不按注释行数机械凑数。
5. **测试与文档随阶段提交。** 保留全量既有回归，新增关键路径的正常/边界/失败测试。真实 GPU/Host 检查不能由替身单测代替。
6. **只使用公开边界。** 不引用 Host 内部对象、Dock 实现，也不静默修改 Host 共享程序集策略或插件协议。
7. **当前只有 Debug 开发验证。** 不使用 AIFLOW、Windows CI、Windows Smoke、Release Acceptance、Release 构建、正式 ZIP、统一 verify/seal 或发布门禁。
8. **不满足阶段出口就不签署。** 未验证、失败和完成分别记录；不能删 DLL、删测试、隐藏视口或降级目标来制造通过。

严格顺序为 **G0 → G1 → G2 → G3 → G4 → G5**。只有前一阶段的完成条件全部满足，才进入下一阶段。
发布是未来独立任务，不是 G5 自动触发的动作。

| 阶段 | 当前状态 | 可交付成果 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| G0 设计基线 | 已完成 | 规则、架构、开发约束、测试矩阵和专项文档 | 文档一致、链接有效、未实现状态明确 |
| G1 集成可行性 | 原型已实现；阻塞 | 合规私有依赖目录、可用的嵌入后端、同一页面在 Standalone/真实 Host 运行 | 两个阻塞解决，叠层/Dock/DPI/20 次开关等矩阵通过 |

## 5. G1 剩余路线：先解决可接入问题

### G1.1 解决依赖交付冲突

**问题事实：** 当前 Stride 传递依赖包含 `Microsoft.Extensions.DependencyModel.dll`，Build 1.1.3 禁止插件携带
`Microsoft.Extensions.*`，目标 Host 的 Debug 输出又没有该文件。保持完整声明的隔离部署已返回失败。

实施步骤：

1. 从锁文件、`project.assets.json` 与构建 targets 重新核对实际运行闭包、Host 共享闭包及 RID，固定可复现版本。
2. 评估公开受支持的处理方式：由独立 SDK/Build 兼容性变更精确区分共享依赖与业务私有依赖，或找到经过实际验证的引擎包组合，确实不再产生该依赖。
3. 若需要 Host/SDK 改动，单独记录变更范围、共享身份规则和兼容测试；当前小镇分支不能擅自修改宿主加载器，也不能仅靠文件名前缀猜测真实共享身份。
4. 调整确定方案后更新私有包声明、锁文件、依赖清单及许可记录；不得只从复制清单删掉缺失 DLL。
5. 用 Build 协议生成经过绝对路径核验的隔离 Debug 暂存目录，审查是否缺文件、是否私带共享程序集、是否夹带非 win-x64 原生文件。

完成条件：完整 Debug 部署通过；独立渲染 DLL、内容及许可证都进入正确相对路径；在真实 Host 的插件 ALC 中能加载，失败诊断定位到当前插件。
仅在 Standalone bin 中运行不满足此条件。

### G1.2 解决视口叠层与合成

**问题事实：** 当前 NativeControlHost 方案会盖住页面内的 Avalonia 红色叠层，不能直接视为最终后端。

实施步骤：

1. 保留当前原型和失败截图作为对照，明确必须支持的 Host 弹窗、命令面板、Dock 拖放提示和页面提示层。
2. 优先评估 Stride 渲染结果通过 GPU 纹理接入 Avalonia 合成的最小实验；接口可用性、图形设备匹配、同步原语和资源所有权都先验证，不预设某个 API 一定可用。
3. 若改用共享纹理，先处理创建/销毁、像素尺寸、DPI、帧同步、旧纹理回调、设备丢失，再接回现有房屋。
4. 若公开 SDK 已有可满足全部叠层与迁移要求的协调机制，也需完成同一矩阵后比较成本，不能只修复单个弹窗。
5. 在专用记录中选定唯一生产候选后端，写明线程和资源所有者；原生原型可继续作为诊断入口，但不与正式页面形成两套游戏逻辑。

完成条件：页面叠层和 Host 关键 UI 正常覆盖、点击、获得焦点；切换/隐藏不重复渲染或吞宿主快捷键；没有每帧 CPU 截图复制。
若当前公开边界不足以完成嵌入，记录最小复现及所需 SDK 能力，G1 继续保持阻塞，不静默改为外部游戏窗口或其他引擎。

### G1.3 完成真实 Host 与生命周期矩阵

前置条件：G1.1、G1.2 已通过。使用独立 Host 输出和独立数据目录，不覆盖日常插件或用户布局。

| 检查组 | 必须覆盖 |
| --- | --- |
| 页面与焦点 | 首次打开、再次打开冲突提示、旋转/缩放输入、按钮焦点、宿主快捷键、隐藏和最小化 |
| Dock 与布局 | resize、零尺寸恢复、浮动、重停靠、迁移中关闭、命令面板与拖放提示 |
| DPI | 100%、150%、200%；明确 DIP/物理像素与纹理/交换链尺寸关系 |
| 故障与恢复 | 缺资源、初始化中止、帧异常、资源清理异常、显式重试、不接收已关闭表面的迟到回调 |
| 稳定性 | 预热后基线、至少 20 次打开/关闭、循环后及空闲后的线程/窗口/句柄/内存，以及可取得的显存指标 |

完成条件：没有持续增长或残留活动表面；异常局限于当前小镇页面；其他游戏仍可用；未测硬件项如实记录且不签署缺失的必测项。
更新 G1 专项记录为“通过”后，才能开始 G2。

## 6. G2 路线：先完成无图形的完整对局

目标：纯规则可以从开局推进到终局，不依赖 Avalonia、Stride、文件系统、线程或真实时钟。
首版按主方案采用 24 格、一名真人两名电脑、整数金额、最多 30 轮；规则数值只保留一个配置来源。

| 工作包 | 实施内容 | 验收重点 |
| --- | --- | --- |
| G2.1 地图与状态 | 小镇自己的格子/玩家/地产/阶段/快照，固定地图配置及输入校验 | 24 格唯一，初始金额/归属正确，外部不能直接修改状态 |
| G2.2 随机与回合 | 小型版本固定的可恢复随机源、掷骰、绕圈奖励、出局跳过、轮次推进 | 固定向量、随机上下界、恢复续序；非法命令不消耗随机数 |
| G2.3 交易与升级 | 购买、放弃、租金、每回合升级上限、两级建筑、出售 | 恰好够钱、不足一元、本人地块、重复点击、非法操作零副作用 |
| G2.4 债务与终局 | 银行/玩家债权、出售偿债、破产清算、地块回收、30 轮排名及同分 | 入账一次、无负余额、部分清算正确、淘汰者不再行动 |
| G2.5 会话与电脑 | 单一提交入口、不可变结果/有序事件、简单电脑决策 | 真人与电脑走同一规则入口；AI 不直接改钱，不窥视未来随机值 |
| G2.6 完整模拟 | 至少 1,000 个固定种子全电脑对局 | 在约定上限内结束；金额、归属、阶段不变量持续成立；输出失败种子和可复现命令 |

朴素实现顺序：纯配置/快照 → 纯规则 → 可恢复随机 → 串行会话 → 普通电脑决策器。
有序事件只在当前小镇对局内传递，不建设跨游戏事件总线。

阶段出口：全部规则与失败路径测试通过；覆盖率按规则、债务、随机、非法输入分层审查；没有靠 GPU 或手动点击才能发现的规则依赖。
同步 G2 专项文档和主规则说明后进入 G3。

## 7. G3 路线：形成可玩 3D 游戏

前置条件：稳定的 G1 后端及已通过测试的 G2 会话。

| 工作包 | 实施内容 | 验收重点 |
| --- | --- | --- |
| G3.1 棋盘与实体映射 | 24 格程序生成棋盘、编号/坐标对应、三个可区分棋子、归属与建筑等级 | 格子索引与领域完全一致；材质/图标不能仅靠颜色表达玩家身份 |
| G3.2 最少美术资产 | 少量房屋和汽车；记录每份来源、许可、摘要、转换方式 | 开发期转换，运行时离线读取；不要先引入大批未经验证素材 |
| G3.3 镜头与输入 | 拖动旋转、缩放、复位、视口焦点与拾取边界 | 不吞 Host 快捷键；DPI 与 resize 后操作正确 |
| G3.4 动画与事件 | 棋子沿格移动、骰子结果展示、购买/升级反馈、有界动画队列 | 规则先提交，动画只回放；跳过、隐藏、取消不再次收租或推进回合 |
| G3.5 中文页面 | 玩家信息、现金、地产详情、掷骰/购买/放弃/升级/出售/结束回合，宽窄布局 | 按真实阶段启用操作；债务状态可理解；按钮能用键盘操作 |
| G3.6 完整体验 | 真人和两名电脑完成一局，展示胜负、破产及同分 | 快速重复操作、动画中关闭、旧回调不能污染新状态 |

阶段出口：真实完整对局通过，渲染错误不改变已提交领域结果，新的规则修改同步配置和语义测试。
G1 诊断按钮不能混在最终游戏操作区中；诊断入口与正式页面职责保持明确。

## 8. G4 路线：将原型 Document 升级为正式入口

保留现有 DocumentTypeId，使用公开 SDK 的实际契约；接口名称与保存握手须以实施时锁定的 SDK 为准。

| 工作包 | 实施内容 | 验收重点 |
| --- | --- | --- |
| G4.1 激活与所有权 | Document Scope 拥有会话、取消源和正式单实例租约；View 只拥有当前表面 | 同时两个激活请求最多一个成功；失败/关闭归还正确资源，不限制其他游戏 |
| G4.2 存档 DTO | 版本、地图配置身份、玩家/地产/轮次/阶段、待购买/待偿债状态、随机算法与内部状态 | 不保存控件、GPU、计时器或仅保存种子；加载前整体校验 |
| G4.3 保存与恢复 | 保存修订、初始化/恢复取消、未知版本、坏字段、并发保存 | 旧保存结果不能覆盖新修订；坏存档不污染当前对局；恢复后随机与回合连续 |
| G4.4 工作台命令 | 接入正式 Restart，精确路由到当前小镇 Document | 取消旧 AI/动画、提升会话代数、迟到结果无效；不伪造 Undo，不新增默认快捷键 |
| G4.5 各入口一致 | Host/Standalone 复用正式 View/Document，更新显示名、实际注册计数与文档 | 不复制实现；不把原型和正式游戏登记成两个独立游戏 |

阶段出口：SDK 契约、存档故障、命令可用性、修订竞争及生命周期全部通过；现有十四个游戏全量回归通过。

## 9. G5 路线：本地开发完成与自包含核验

目标：得到可复现、可以在隔离 Host 使用的 Debug 插件目录，并说明其实际平台前提。
“尽可能自包含”不能解释为私带 Host 共享程序集，也不能承诺无需操作系统、显卡驱动或 .NET 运行时。

| 工作包 | 实施内容 | 验收重点 |
| --- | --- | --- |
| G5.1 固定交付文件 | 从实际依赖图生成 Debug 目录，核对托管/原生/内容/许可及摘要 | 不复制整个 bin；不夹带编辑器、测试程序集或无用模型；不缺传递运行文件 |
| G5.2 原生闭包 | 审查 P/Invoke 路径、原生 DLL 导入表二级依赖和 VC++ 运行库 | 明确可随插件携带与外部前提；不改全局 PATH/当前目录，不扫描其他插件 |
| G5.3 环境验证 | 无编辑器/无 NuGet 缓存的离线环境、只读安装目录、中文与空格路径 | 没有运行时联网下载；缓存写明确可写位置；失败提示可诊断 |
| G5.4 性能与资源 | 完整对局压力、隐藏负载、Dock 迁移、设备异常、至少 20 次开关 | 记录机器、分辨率、线程/句柄/内存/可取得的显存；不虚构帧率或零增长 |
| G5.5 最终同步 | 完整测试、覆盖率审查、使用说明、已知限制、素材许可和阶段记录 | 文档与代码计数、目录、行为、命令一致；所有失败已解释或仍明确阻塞 |

阶段出口：可玩的简单 3D 游戏、可靠的 Document/存档、全量测试与本地真实环境证据全部完成。
结论只能是“本地开发验证完成”，**不会自动取得发布资格**。

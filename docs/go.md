# 围棋 Document 设计与开发说明

## 功能边界与规则口径

围棋以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.go`。每次打开 Document 都创建一局彼此隔离的本地双人对局；关闭后停止计时、
取消仍在播放的视觉动画并释放 ViewModel。

首版固定使用 19×19 交叉点，黑方先手，不提供让子。规则采用适合本地休闲对局的中国数子口径：

- 棋子只按上下左右连接成棋组，棋组共享相邻空点形成的“气”。
- 落子后先提走所有无气的相邻对方棋组，再检查新形成的己方棋组；没有提子且己方仍无气属于自杀，落子无效。
- 每次落子后的棋盘不能与当前对局分支中任何历史棋盘完全相同，即位置全局同形禁着；停一手不参与重复判断。
- 任意合法落子都会把连续停手数清零；双方连续停一手后进入死子标记与数子阶段。
- 数子阶段点击任一棋子会整体切换其正交连接棋组的死子标记。双方可以确认结果，也可以清除标记并恢复对局。
- 中国数子法按“活子数 + 只与己方接触的围空”计分；双方共同接触的空区为中立点，提子数只展示、不重复加分。
- 白方固定贴 7.5 目，因此确认数子后不会产生和棋。行棋阶段当前方也可以认输，由对方中盘获胜。

首版提供不限步撤销、停一手、认输、恢复对局、确认结果、重新开始、累计有效行棋时间、双方提子数、落子数和操作记录。
不提供 AI、联网、账号、旁观、让子、9/13 路棋盘、双方棋钟、读秒、SGF、存档、战绩、排行榜、音效或棋力分析。

## SOLID 职责与朴素设计

围棋与其他小游戏平级，内部按领域、页面编排和绘制边界组织：

```text
Features/Go/
├─ Domain/
│  ├─ GoModels.cs          # 棋子、坐标、不可变快照、落子与终局结果
│  ├─ GoRules.cs           # 棋组、气、提子、自杀与全局同形
│  ├─ GoScorer.cs          # 死子移除、空区归属与中国数子
│  └─ GoGame.cs            # 当前状态、历史棋盘键与不限步撤销
├─ ViewModels/
│  ├─ GoGameTimer.cs       # 基于 TimeProvider 的累计时间
│  ├─ GoAnimationPlan.cs   # 与控件和墙钟无关的纯动画进度
│  └─ GoViewModel.cs       # 命令、阶段编排、文案和展示投影
├─ Views/                  # AXAML、SDK 包装 View 与专用棋盘控件
└─ GoDocument.cs           # Plugin SDK 生命周期适配器
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `GoRules` | 纯棋盘合法性、棋组、气、提子和同形验证 | 历史栈、计时、文案和绘制 |
| `GoScorer` | 按已确认死子计算活子、围空、中立点和贴目 | 判断棋组死活、修改棋局或接受输入 |
| `GoGame` | 原子提交领域动作并保存快照与同形历史 | Avalonia、动画、计时和操作记录 |
| `GoGameSnapshot` | 隔离保存棋盘、阶段、计数、死子和结果 | 修改真实棋局 |
| `GoGameTimer` | 累计有效行棋时间 | UI 刷新和阶段判断 |
| `GoAnimationPlan` | 给出固定时长与纯进度函数 | 创建计时器或改变棋盘 |
| `GoViewModel` | 命令、状态流、计时、动画通知与中文投影 | 复制提子、同形或数子算法 |
| `GoBoardControl` | 绘制、命中、提示和动画回放 | 判断落子是否合法或计算分数 |
| `GoDocument` | Host 标题、ViewModel 所有权与释放 | 游戏规则和页面命令 |

只有一个规则和一个计分实现，因此不创建空洞的 Strategy 接口。项目也不抽取通用游戏框架，不引入仓储、事件总线、
Mediator、抽象工厂或 State 类层次。`TimeProvider` 是已有的轻量测试接缝，不建立额外时钟接口。

## 落子、全局同形与历史

一次落子领域事务严格按以下顺序执行：

1. 检查坐标、行棋阶段和交叉点占用。
2. 在棋盘副本放入当前方棋子，逐个检查正交相邻的对方棋组，并完整提走已经无气的棋组。
3. 重新计算新棋子所属棋组的气；若仍为零则拒绝自杀。
4. 把模拟棋盘编码为 361 字符稳定键；若当前分支已经出现该棋盘，则拒绝位置全局同形。
5. 只有全部验证通过后，才保存历史帧并一次性提交新快照、提子数、最近落子、手数、回合与历史棋盘键。

同一对方棋组可能从新落点的多个方向相邻，提子时使用集合去重，保证只移除和计数一次。非法落子从不写棋盘、提子数、
撤销栈或同形集合。停一手不写入棋盘键，但它本身以及标记死子、恢复对局、确认结果和认输都是可撤销的有效状态操作。

每个历史帧同时保存完整快照和当时的棋盘键集合。撤销后创建新分支时，已经被撤销分支独有的棋盘不会残留在同形集合中；
当前真实分支出现过的棋盘仍然受禁着约束。完整拷贝最多覆盖 361 个格子，本地单局规模固定且可控，优先选择容易审计的正确性，
不引入增量棋盘或 Zobrist 碰撞处理复杂度。

## 数子、恢复与计时

第二次连续停一手提交后，回合自然切换到下一方并进入 `Scoring`。页面在该阶段停止累计行棋时间、禁止普通落子，改为允许：

- 点击棋子，整体标记或取消其连接棋组为死子；
- “确认结果”，先把标死棋子视为空点，再计算空区归属、双方区域分、白贴 7.5 目、胜者和胜差；
- “恢复对局”，清空全部死子标记与连续停手数，由自然的下一方继续，计时从此前累计值恢复。

空区洪泛搜索收集边界颜色：只接触黑棋归黑，只接触白棋归白，同时接触双方或没有边界棋子均为中立点。该算法不尝试替玩家
判断死活或双活；本地双方通过死子标记和恢复行棋共同处理争议。确认结果与认输都形成可撤销快照，撤销后按恢复的阶段决定
计时是否继续。重新开始才会清空累计时间和操作记录。

## UI 与轻量动画

- 顶部工具栏提供重新开始、撤销、停一手、认输、恢复对局、确认结果和“启用动画”，并显示阶段、回合和总用时。
- 状态栏显示双方提子数、落子数、最近反馈与终局比分。右侧始终显示规则速览和本局操作记录。
- 专用控件绘制木色 19 路网格、标准九星、A–T 且跳过 I 的列坐标、从下向上 1–19 的行坐标、悬停预览和最近落子红点。
- 数子阶段的死子以半透明棋子和红叉显示；确认数子后使用小方块显示空点归属，中立点不着色。
- 有效落子使用 140ms 缩放淡入；若发生提子，再用 180ms 将被提棋组缩小淡出。动画期间禁止新的棋盘输入。
- 领域结果在动画开始前已经原子提交。撤销、重开、关闭动画或控件卸载只停止视觉计时并直接呈现最终快照，不回滚领域事务。
- Light/Dark 主题分别定义面板、文字和边框资源；木色棋盘保持稳定。固定 650×650 棋盘在小窗口中通过双向滚动访问。

## Plugin 与 Standalone 集成

- `PluginIds.GoDocument` 冻结为 `myavalonia.plugin.classic.game.document.go`。
- Plugin Module 在五子棋之后注册第五个普通 Document，菜单分类保持“经典游戏”。
- Standalone 第五个“围棋”页签直接创建正式 `GoDocument`，复用同一份 ViewModel、View、棋盘控件和领域代码。
- Standalone 关闭时释放它拥有的围棋 Document；真实 Host 仍负责最终的 Document Scope、Dock 和加载上下文验收。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 棋组与气 | 中央、边角、连接、共享气和空点 |
| 落子与提子 | 单子、多子、同时邻接去重、占用、越界、自杀、提子后获得气和零副作用 |
| 全局同形 | 历史棋盘拒绝、停手豁免、撤销恢复与分支隔离 |
| 状态历史 | 落子、停手、标死、恢复、确认、认输、不限步撤销和新局清空 |
| 中国数子 | 活子、单色围空、双方中立、死子移除、7.5 贴目、胜者与胜差 |
| ViewModel | 双人回合、命令阶段、计时、记录、非法反馈、动画锁定、释放与多实例隔离 |
| UI/Document | 十九路命中、边界拒绝、跳过 I、默认/Host 标题、包装绑定、释放、稳定 ID 和第五个注册 |
| 文档 | 根说明、文档索引、专项设计、非发布边界与 AIFLOW 禁止项 |

开发阶段只执行：

```powershell
dotnet build -c Debug -warnaserror
dotnet test -c Debug --no-build --no-restore
```

当前不是发布阶段，不增加或运行 Windows CI、覆盖率阈值、Release 构建、ZIP 打包、Host 部署或发布门禁。本功能不使用
AIFLOW，不创建或修改 `.aiflow` 内容。

## 手工体验检查

1. 启动 Standalone 第五个“围棋”页签，确认 19 路网格、九星、跳过 I 的列坐标、规则速览和黑方先手。
2. 在中央、边和角构造打吃、连接、单子与多子提取，确认提子数、最近落子、回合和记录一致。
3. 构造真自杀、打劫和更长循环，确认非法落子说明准确且棋盘、手数和历史不变。
4. 开关动画，确认落子淡入、提子淡出、动画期间输入锁定，以及撤销、重开和切换页签不会留下锁定。
5. 双方连续停一手，标记和取消整组死子；确认围空、中立点、白贴 7.5 目、胜者和胜差显示正确。
6. 从数子阶段恢复对局并继续落子；逐步撤销恢复、标死、停手、落子、确认结果和认输。
7. 在浅色、深色主题和较小窗口检查棋盘、工具栏、规则与记录均清晰且可滚动。
8. 在真实 Host 打开多个围棋 Document，确认棋盘、同形历史、计时、动画和记录互不影响。

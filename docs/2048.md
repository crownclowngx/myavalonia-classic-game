# 2048 Document 设计与开发说明

## 功能边界与经典规则

2048 以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.2048`。每次打开 Document 都创建一局独立游戏；本游戏没有计时、后台任务和
外部资源，关闭后不需要额外释放。不提供撤销、最高分持久化、存档、排行榜、触控滑动、音效、分数跳动或庆祝特效。
界面默认提供短促的滑动、合并和新生方块动画，并允许在当前 Document 内随时关闭。

首版固定使用 4×4 棋盘。新局在两个不同空格各生成一个方块；玩家每次向上、下、左或右推动整张棋盘。所有非空方块先向
目标边缘压缩，随后相邻同值方块从目标边缘开始成对合并。同一方块每次移动最多参与一次合并，例如
`2,2,2,2` 向左得到 `4,4,0,0`，而不是 `8,0,0,0`。每次合并把新方块的数值累加到当前分数。

只有棋盘实际变化的移动才会在均匀选择的空格中生成一个新方块：90% 为 2，10% 为 4。无效移动不生成方块、不加分，
也不改变游戏阶段。首次合成 2048 后暂停方向输入并显示“继续游戏”；玩家确认后可以继续合成更高数字，且不重复提示。
棋盘没有空格，并且不存在水平或垂直相邻同值方块时游戏结束。

## SOLID 职责与朴素设计

2048 是与其他小游戏平级的独立功能域，不修改现有游戏，也不抽取通用棋盘框架：

```text
Features/Game2048/
├─ Domain/                  # 纯移动规则、单局状态和方块生成策略
├─ ViewModels/              # 页面投影、动画计划和最后输入缓存
├─ Views/                   # AXAML 布局、局部输入和动画视觉回放
└─ Game2048Document.cs      # Plugin SDK 标题与 ViewModel 所有权适配
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `Game2048Rules` | 纯计算四方向压缩、单次合并、分数增量、可移动性和方块轨迹 | 随机生成、真实棋盘提交、文案和 UI |
| `Game2048Game` | 持有单局棋盘、分数和阶段，原子提交带前后快照的 Transition | 键盘、动画计时、颜色和 Plugin SDK |
| `ITileSpawnStrategy` | 从只读空格集合选择一个 2/4 方块 | 修改棋盘、合并、计分和终局判断 |
| `RandomTileSpawnStrategy` | 均匀选空格并实现 90%/10% 数值概率 | 信任或提交策略结果 |
| `Game2048Transition` | 隔离保存前后棋盘、移动轨迹、合并目标和新生方块 | 播放动画或修改已提交状态 |
| `Game2048AnimationPlan` | 提供固定阶段、持续时间和纯进度函数 | 调度线程、创建控件或修改棋盘 |
| `Game2048ViewModel` | 命令、状态文案、动画开关、最后方向缓存和 16 格投影 | 重复实现压缩、合并或插值绘制 |
| `Game2048CellViewModel` | 数字、颜色、字号和无障碍说明 | 修改领域棋盘 |
| `Game2048View` | 布局、局部输入、三层棋盘和计时回放 | 全局快捷键、移动规则和领域回滚 |
| `Game2048Document` | Host 标题和独立 ViewModel 所有权 | 玩家命令、游戏规则和虚假的资源释放 |

- **单一职责：** 纯规则、可变对局、随机选择、动画计划、视觉回放、输入设备和 Host 生命周期按真实变化原因拆分。
- **开闭原则：** 随机生成可以通过窄策略替换；新游戏继续建立同级功能域，不修改 2048 容纳其他玩法。
- **里氏替换：** `Game2048Document` 只遵守普通 `IPluginDocument` 语义，不声明保存能力或无实际资源的释放行为。
- **接口隔离：** 只为生产随机和确定测试都需要的生成能力建立接口；规则、棋盘、ViewModel 和 Document 不创建空洞接口。
- **依赖倒置：** 游戏引擎依赖生成能力，不依赖 `Random.Shared`；测试可以精确指定生成位置和值。

使用的设计模式仍只有朴素的 Strategy。动画计划只是一次 Transition 的只读表现数据，不引入动画框架、State 类层次、
事件总线、Mediator、仓储、工厂或跨游戏基类。

## 状态、事务与数据流

```text
Playing --首次合成 2048--> WonAwaitingContinue --确认且仍可移动--> Continuing
   |                               |                                  |
   └──补充方块后无合法移动─────────┴──确认时已无合法移动───────────────> Lost

任意状态 --重新开始--> Playing（零分、两个新方块）
```

一次有效移动按以下顺序完成：

1. `Game2048View` 仅在焦点位于自身视觉子树时，把方向键或 W/A/S/D 映射成 ViewModel 命令；方向按钮复用同一命令。
2. ViewModel 把抽象方向交给 `Game2048Game`，不读取键盘，也不推导合并结果。
3. `Game2048Rules` 从原棋盘复制候选数组，逐行或逐列压缩、成对合并，并记录每个原方块的起点、终点与合并目标。
4. 若候选棋盘与原棋盘相同，立即返回，不调用生成策略。
5. 游戏把候选棋盘的空格交给策略，并再次校验坐标在界内、位置仍为空、数值只能为 2 或 4。
6. 移动、生成、计分和阶段计算全部成功后，一次覆盖真实棋盘，并返回不可变的前后快照、轨迹和新生方块。策略返回非法
   结果或抛出异常时，原棋盘和分数保持不变，也不会产生 Transition。
7. 动画关闭或没有 View 订阅时，ViewModel 立即刷新最终投影；否则保留移动前投影并发出 `Game2048AnimationPlan`。
8. View 隐藏落定层，在 Canvas 中用 110ms 减速插值回放移动，再用 90ms 同时播放合并弹跳和新生缩放；完成或取消后
   清空临时层并通知 ViewModel 刷新最终状态。
9. 动画期间的输入只覆盖保存最后一个方向。当前动画落定后再提交该方向；若已进入胜利确认或终局，则自然丢弃。

胜利移动会先完成本次随机生成，再进入等待确认状态。等待期间方向输入无效，但可以重新开始。继续确认后若棋盘已经无解，
直接进入 `Lost`；否则进入 `Continuing`，后续出现 2048 或更高方块都不会再次阻断输入。

## UI、输入与 Plugin 集成

- 棋盘使用 4×4 `UniformGrid`、Avalonia Border 和 TextBlock 绘制，不包含图片或第三方素材。
- 棋盘分为始终可见的固定空格层、绑定最终状态的落定方块层和仅在约 200ms 回放期间存在的 Canvas 动画层。
- 方块滑动采用三次减速；合并目标按 `1 → 1.12 → 1` 弹跳，移动后新方块按 `0 → 1` 缩放。新局的两枚初始方块直接显示。
- 2 至 2048 使用经典辨识色，超过 2048 使用稳定深色回退；数字位数增加时自动缩小字号。
- 页面面板和文字提供独立 Light/Dark 主题资源，不依赖 Host 私有颜色键；棋盘经典底色保持固定。
- 棋盘可点击获取焦点。View 在自身视觉子树的隧道路由中处理方向键和 W/A/S/D，仅消费这八个按键；没有注册应用级快捷键。
- 可点击方向按钮保证未获得棋盘焦点或不便使用键盘时仍可操作；无效状态下按钮禁用。
- “动画效果”默认开启，只保存在当前 ViewModel。播放中关闭会立即显示最终棋盘并无动画执行最后缓存方向。
- 重新开始会取消回放并清空缓存；切换 DataContext 或离开视觉树时，View 停止自己的 DispatcherTimer 并安全落定。
- 状态区展示当前分数、阶段文案、按条件出现的“继续游戏”和始终可用的“重新开始”。空间不足时外层滚动区域承载固定棋盘。
- Plugin Module 将 2048 注册为第七个普通 Document；Standalone 第七个页签复用正式 Document、ViewModel、View 和领域代码。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 开局与生成 | 两个不同初始格、2/4 数值、空格均匀索引、90%/10% 分界 |
| 移动与合并 | 四方向、空格压缩、双对合并、三连/四连、每方块单次合并、分数增量 |
| Transition | 普通/静止轨迹、双来源同目标、合并目标、随机新生记录、前后快照隔离、无效移动无结果 |
| 原子性 | 无效移动不生成、非法坐标、占用格、非法数值、异常时棋盘与分数不变 |
| 胜利与终局 | 首次 2048 暂停、继续挑战不重复提示、满盘有解、满盘无解、继续时无解 |
| 生命周期 | 重开、双方块零分、多实例隔离、默认/Host 标题、无虚假 IDisposable |
| 动画计划 | 阶段顺序、110/90ms 边界、滑动缓动、合并缩放、新生缩放、完成判断 |
| ViewModel/View | 默认开关、即时模式、动画请求/取消、最后输入缓存、重开/终局、三层清理、方向键/WASD |
| 插件组合 | 第七个普通 Document、稳定 ID、描述分类、包装单向绑定、Standalone 编译 |

当前开发阶段只执行：

```powershell
dotnet restore
dotnet build -c Debug -warnaserror --no-restore
dotnet test -c Debug --no-build --no-restore
```

本功能不使用 AIFLOW，不创建或修改 `.aiflow` 内容。当前不是发布阶段，不创建或运行 Windows CI，不设置覆盖率阈值，
不执行 Release 构建、ZIP 打包、Host 部署或发布验收。

## 手工体验检查

1. 启动 Standalone 第七个“2048”页签，确认棋盘恰有两个值为 2 或 4 的初始方块，分数为零。
2. 单击棋盘后分别使用方向键和 W/A/S/D，确认四向移动一致；再用方向按钮完成同样操作。
3. 验证空格压缩、双对和三连合并语义，确认有效合并正确加分，无效方向不生成新方块。
4. 合成 2048，确认方向输入暂停；点击“继续游戏”后可以继续移动且不会再次弹出确认。
5. 确认有效移动平滑滑动、合并方块轻微弹跳、新生方块缩放出现；快速连续输入只在下一段执行最后方向。
6. 在播放中关闭“动画效果”，确认立即落定且之后无延迟；重新开启后恢复动画，重开仍保留开关值。
7. 在播放中切换页签或 DataContext，确认没有残留方块、后台计时或锁死输入。
8. 走到无合法移动，确认显示游戏结束并禁用方向输入；重新开始恢复双方块和零分。
9. 分别使用浅色、深色主题和较小窗口，确认文字、棋盘、大数字、按钮和滚动行为清晰可用。
10. 在真实 Host 打开多个 2048 Document，确认动画开关、棋盘、分数、胜利确认和终局状态互不影响。

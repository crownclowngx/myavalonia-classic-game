# 五子棋 Document 设计与开发说明

## 功能边界与规则口径

五子棋以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.gomoku`。每次打开 Document 都创建独立棋局；关闭后取消电脑搜索并释放计时资源。

棋盘固定为 15×15 个交叉点，黑方先手但第一手不强制天元。首版提供两套规则：

- **自由规则：** 黑白任一方横、竖或斜线连续五枚及以上即获胜。
- **禁手规则：** 黑方恰好五连获胜；未同时形成合法五连时，长连、双四和双三不可落。白方没有禁手，五连及以上获胜。
  活三必须能通过一个本身合法的后续点形成两端均可成五的连续四子，靠近边界、白棋或后续禁手点的假活三不计入双三。

首版支持本地双人和人机对战。人机模式可选玩家执黑或执白，并提供简单、中等、困难三级电脑。辅助功能包含稳定提示、
单步撤销、回退暂停/继续、全局计时、总步数、禁手原因和局内操作记录。不提供存档、持久战绩、排行榜、联网、职业交换开局、
自定义棋盘、棋谱回放、重做、认输、音效或复杂动画。

## SOLID 职责与朴素设计

五子棋与其他小游戏平级并保持独立领域：

```text
Features/Gomoku/
├─ Domain/                 # 纯规则、禁手、不可变快照、单步历史和三级 AI
├─ ViewModels/             # 模式、人机编排、回退暂停、计时和展示投影
├─ Views/                  # AXAML、专用绘制控件和输入转发
└─ GomokuDocument.cs       # Plugin SDK 生命周期适配器
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `GomokuRules` | 胜负、合法性、禁手、候选点和纯棋形计算 | 撤销栈、AI 任务、计时和 UI |
| `GomokuGame` | 持有当前快照、提交落子和恢复一手历史 | 游戏模式、后台线程和文案 |
| `GomokuGameSnapshot` | 隔离保存 225 点、回合、状态、获胜线和规则 | 修改真实棋局 |
| `IGomokuMoveStrategy` | 从只读快照选择一个合法点 | 提交落子、切换回合或操作 UI |
| `GomokuGameTimer` | 基于 `TimeProvider` 累计有效对局时间 | UI 调度和胜负判断 |
| `GomokuViewModel` | 命令、异步电脑、回退暂停、计时、记录和展示投影 | 重复实现禁手或胜负规则 |
| `GomokuBoardControl` | 绘制棋盘、命中测试并转发交叉点 | 判断合法性和修改领域对象 |
| `GomokuDocument` | Host 标题、ViewModel 所有权和释放 | 游戏规则、命令和展示属性 |

三级电脑确有三个生产实现，因此使用窄 Strategy 接口。项目没有为棋盘、计时或 Document 创建空洞接口，也没有引入通用游戏
框架、仓储、事件总线、Mediator、抽象工厂或 State 类层次。禁手递归和 alpha-beta 是规则/算法本身，不扩展成通用框架。

## 规则、禁手和单步历史

一次领域落子按以下顺序执行：

1. 检查棋局未结束、当前方正确、坐标在棋盘内且交叉点为空。
2. 禁手规则且黑方落子时，在棋盘副本上假设落子；若形成恰好五连则优先合法获胜。
3. 未获胜时依次识别长连、两个独立的四形，以及至少两个真实活三；任一禁手原因都会拒绝提交且保持零副作用。
4. 合法落子前保存不可变快照，一次写入棋子、最近落子、步数、下一回合和全部获胜线。
5. 形成胜线或棋盘放满后结束；否则切换另一方。

双四按不同方向或不同四子集合计数，开放四的两个成五端点仍属于同一个“四”。双三不会只匹配表面模板：当前三必须能补成
连续四子，两端都能合法形成恰好五连，补四点自身还要递归通过黑方禁手验证。一次全盘禁手扫描共享派生棋形缓存，并先用
“当前四格窗口恰有三黑一空、两端开放”的必要条件剪枝，避免无意义搜索。

`GomokuGame` 每次成功落子保存一个完整快照。本地双人撤销一手后立即按恢复回合继续；人机模式也严格只回退一手，但进入
页面级回退暂停。暂停期间玩家和电脑均不能落子、计时停止，可继续逐手撤销；点击“继续对局”后才恢复当前玩家输入或启动
电脑。电脑思考期间撤销会取消搜索并增加对局版本，旧任务不能提交。

## 电脑、提示与计时

- 简单：从已有棋子两格邻域内的合法点随机选择；空盘选择中心，测试注入固定随机源。
- 中等：稳定比较立即取胜、阻挡立即失败、活四、冲四、活三、普通连子和中心距离，同分按行列排序。
- 困难：以中等策略为保底，使用迭代加深 Negamax、alpha-beta 剪枝、候选排序和单次搜索缓存；生产单手约两秒软上限，
  超时返回最后完整深度，取消则立即放弃结果。

所有策略只读取不可变快照，最终落点仍由领域再次验证；禁手规则下电脑执黑不会返回禁手。困难策略的测试构造函数支持固定
深度和节点预算，使自动化测试不依赖真实两秒墙钟。提示固定使用中等策略，只高亮建议点和显示坐标，不落子、不计步、
不写操作记录。

计时从第一手成功提交后开始，包含后续电脑思考时间，终局、回退暂停和 Document 释放时停止。回退不会倒扣已消耗时间；
继续后在非空、未结束棋局上恢复累计。只有新局或配置切换才清零。

## UI 与 Plugin 集成

- 工具栏提供规则、模式、难度、玩家颜色、重新开始、撤销、继续对局、提示、状态、回合和耗时。
- 状态区显示黑白数量、总手数、禁手/提示消息和终局结果，右侧记录落子、撤销、继续和终局事件。
- 专用控件绘制木色 15×15 网格、A-O/1-15 坐标、五个星位、棋子、悬停预览、最近落子、提示圈、禁手红叉和全部获胜线。
- 黑方可操作且启用禁手规则时显示全部禁手点；悬停和点击反馈具体原因，领域仍会再次拒绝提交。
- 工具区与记录区提供 Light/Dark 资源，木色棋盘保持稳定；固定 570×570 棋盘在空间不足时由滚动区域承载。
- Plugin Module 注册第四个普通 Document；Standalone 第四个页签复用正式 Document、ViewModel、View 和领域代码。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 基础规则 | 任意首手、占用/越界、四方向五连、自由长连、白方长连、满盘平局 |
| 禁手 | 长连、双四、双三、假活三、边界、四三合法、合法五连优先、零副作用 |
| 快照与撤销 | 数组隔离、单步恢复、终局恢复、获胜线和多实例隔离 |
| 电脑与提示 | 三级合法性、输入不变、固定随机、立即获胜、防守、禁手规避、取消和预算 |
| ViewModel | 双人、人机黑白方、输入锁定、配置重置、计时、记录、连续回退、暂停/继续和旧搜索隔离 |
| UI/Document | 交叉点命中、边界拒绝、默认/Host 标题、释放级联、包装绑定、稳定 ID 和第四个注册 |

开发阶段只执行：

```powershell
dotnet build -c Debug -warnaserror
dotnet test -c Debug --no-build --no-restore
```

当前不是发布阶段，不增加 Windows CI、覆盖率阈值、Release 构建、ZIP 打包、Host 部署或发布门禁。本功能不使用 AIFLOW，
不创建或修改 `.aiflow` 内容。

## 手工体验检查

1. 启动 Standalone 第四个“五子棋”页签，确认默认自由规则、本地双人、坐标、星位和任意首手。
2. 验证横、竖、两条斜线和长连胜负，确认最近落子、全部胜线、状态、计时和记录同步。
3. 切换禁手规则，构造长连、双四、双三和假活三，确认红叉、原因和禁止点击准确。
4. 切换人机三级难度和玩家颜色，确认玩家执白时电脑先行，电脑思考期间输入锁定且配置切换不写回旧结果。
5. 验证提示不修改棋局；双人撤销一手立即继续，人机每次只退一手并暂停，可连续撤销和继续。
6. 在浅色、深色主题和较小窗口中检查工具栏、棋盘、禁手、胜线和记录仍清晰且可滚动。
7. 在真实 Host 打开多个五子棋 Document，确认规则、棋盘、电脑任务、计时和记录互不影响。

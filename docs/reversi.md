# 黑白棋 Document 设计与开发说明

## 功能边界与规则口径

黑白棋以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.reversi`。每次打开 Document 都创建一局独立游戏；关闭后取消电脑计算并释放计时资源。

首版采用现代奥赛罗规则：8×8 棋盘中央按对角线交错放置四枚棋子，黑方先手。玩家只能落在至少能够沿水平、垂直或
对角线夹住一枚对方棋子的位置；一次落子形成的全部方向必须同时翻转。当前方没有合法位置时自动跳过，不能主动弃权；
双方均无合法位置或棋盘放满时结束，棋子多者获胜，数量相同为平局。

首版支持本地双人和人机对战。人机模式可选择玩家执黑或执白，并提供简单、中等、困难三级电脑。辅助功能包含合法位置、
稳定提示、决策点撤销、全局计时和局内操作记录。不提供联网、自定义棋盘、存档、重做、排行榜或持久战绩。

## SOLID 职责与朴素设计

黑白棋是与扫雷、蜘蛛纸牌平级且互不关联的独立领域：

```text
Features/Reversi/
├─ Domain/                 # 纯规则、不可变快照、撤销和三级 AI
├─ ViewModels/             # 页面投影、人机编排、计时与记录
├─ Views/                  # AXAML 布局和点击转发
└─ ReversiDocument.cs      # Plugin SDK 生命周期适配器
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `ReversiRules` | 计算合法位置、八方向翻转和一步后的回合结算 | 历史、AI、计时和 UI |
| `ReversiGame` | 持有当前快照、提交合法落子、保存和恢复撤销历史 | 人机模式、线程和文案 |
| `ReversiGameSnapshot` | 隔离保存 64 格、回合、状态、步数和最近落子 | 修改真实棋局 |
| `IReversiMoveStrategy` | 从只读快照选择一个合法位置 | 提交落子、切换回合或操作 UI |
| `ReversiGameTimer` | 基于 `TimeProvider` 累计有效对局时间 | UI 调度和胜负判断 |
| `ReversiViewModel` | 命令、电脑任务、设置、计时、棋盘投影和操作记录 | 重复实现夹取规则或 Plugin SDK |
| `ReversiView` | AXAML 展示和格子点击转发 | 判断合法位置和修改领域对象 |
| `ReversiDocument` | Host 标题、初始化、ViewModel 所有权和释放 | 游戏规则、命令与展示属性 |

- **单一职责：** 纯规则、可变棋局历史、策略选择、时间、展示和 Host 生命周期按真实变化原因拆分。
- **开闭原则：** 新电脑强度通过窄策略替换；新增游戏仍建立新的同级功能域，不修改黑白棋容纳其他规则。
- **里氏替换：** `ReversiDocument` 只遵守普通 `IPluginDocument` 生命周期，不引入 Host 不认识的保存语义。
- **接口隔离：** 只有确有三级生产实现和测试替身的电脑选步使用接口，不给棋盘、计时器或 Document 创建空洞接口。
- **依赖倒置：** ViewModel 依赖选步能力，电脑依赖不可变快照；领域不依赖 Avalonia 或 Plugin SDK。

设计模式只有朴素的 Strategy。撤销使用快照栈，状态使用枚举和显式规则，不引入 State 类层次、事件总线、Mediator、
仓储、抽象工厂或通用游戏框架。各游戏分别拥有规则、计时和历史，暂不抽取共享领域能力。

## 状态、落子与回合结算

```text
Ready --第一手合法落子--> Running --棋盘放满或双方无合法位置--> Finished
  ^                            |                                  |
  └────────重新开始/切换设置───┘              撤销───────────────┘
```

一次落子的领域事务按以下顺序执行：

1. 检查棋局尚未结束、坐标在棋盘内、格子为空且落子方是当前方。
2. 从落点向八个方向前进；只有先经过一枚或多枚连续对方棋子，最后遇到己方棋子时，该方向才形成夹取。
3. 在提交修改前收集全部方向的翻转位置；没有任何翻转则拒绝，棋盘和撤销栈均不变化。
4. 保存落子前不可变快照，再一次写入新棋和全部翻转棋子。
5. 优先检查对方合法位置；对方没有而本方仍有时记录自动跳过，并让本方继续。
6. 棋盘放满或双方都没有合法位置时进入 `Finished`，按黑白数量产生胜方或平局。

快照在构造、复制和恢复时复制完整数组。后台 AI、撤销历史和当前棋局不会共享可变棋盘引用。合法位置固定按行优先返回，
让提示、电脑同分选择和测试保持可重复。

## 电脑、提示、撤销与计时

### 电脑策略

- 简单：从当前合法位置随机选择，生产使用 `Random.Shared`，测试可注入固定随机源。
- 中等：依次优先角位、普通边位和内部位置；空角附近的危险格最后考虑，同类位置优先即时翻子更多者，再按行列稳定排序。
- 困难：固定五层 alpha-beta 搜索。叶点评分综合终局胜负、固定位置权重、双方行动力和棋子差；终局权重最高。

电脑只接收不可变快照。ViewModel 使用后台任务运行搜索，困难计算不会阻塞 UI。重新开始、切换模式/颜色/难度或释放
Document 会取消当前搜索并增加对局版本；搜索完成时必须再次匹配版本才能提交，防止旧结果写入新棋局。如果电脑落子后
玩家被自动跳过，电脑循环继续，直到轮到玩家或终局。

提示固定使用中等难度的稳定启发式，只高亮建议格并显示 A1-H8 坐标，不自动落子、不计步、不写操作记录。

本地双人每次撤销一手。人机对战一次撤销完整决策轮：连续恢复快照，直到回到玩家上次落子前；这也覆盖玩家被跳过后电脑
连续多手的局面。玩家执白时，电脑的初始黑棋不属于玩家决策，玩家尚未落子前不能撤销。撤销终局后计时恢复，但已经消耗的
时间不回退；只有新局才清零。

计时从第一手成功落子开始，包含电脑思考时间，终局停止。`DispatcherTimer` 只刷新秒数，真实耗时由 `TimeProvider`
计算。操作记录按时间顺序保存落子序号、颜色/电脑身份、坐标、翻转数、自动跳过、撤销和终局结果，只存在于当前 Document。

## UI 与 Plugin 集成

- 棋盘使用 8×8 `UniformGrid`，绿色格子和代码绘制的黑白圆形棋子，不包含图片或第三方素材。
- 小圆点表示全部合法位置；黄色标记表示提示，蓝色边框表示最近落子。
- 工具栏提供模式、电脑难度、玩家颜色、重新开始、撤销、提示、状态和耗时；人机专属选项在本地双人模式隐藏。
- 状态区显示黑白数量、当前回合、消息和终局比分，旁边提供可滚动局内记录。
- 工具栏和记录区使用插件自己的 Light/Dark 资源；经典绿色棋盘保持稳定对比度，不依赖 Host 私有资源键。
- 状态提交后即时刷新，不建立动画框架。空间不足时由滚动区域承载固定点击尺寸。
- Plugin Module 把黑白棋注册为独立普通 Document；Standalone 使用专用页签承载同一套 Document/ViewModel/View。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 初始与合法步 | 中央四子、黑方先手、四个初始合法位置、稳定行优先顺序 |
| 夹取规则 | 八方向、一次多方向、边界、未封口、空格隔断、占用格和越界 |
| 回合与终局 | 普通切换、自动跳过、同方连续行动、双方无棋、满盘、胜负和平局 |
| 快照与撤销 | 非法操作无历史、数组隔离、逐手恢复、跳过和终局恢复 |
| 电脑与提示 | 三级策略合法性、不修改快照、角位优先、稳定同分、搜索取消 |
| ViewModel | 双人、人机黑白方、输入锁定、连续电脑回合、版本取消、提示和设置重置 |
| 辅助状态 | 计时启停、终局撤销恢复、决策点撤销、操作记录、多实例隔离 |
| Document 与组合 | 默认/Host 标题、释放级联、包装绑定、稳定 ID、普通 Document 注册 |

开发阶段只执行：

```powershell
dotnet restore
dotnet build -c Debug -warnaserror --no-restore
dotnet test -c Debug --no-build --no-restore
```

当前不是发布阶段，不配置或运行 Windows CI，不设置覆盖率阈值，不执行 Release 构建、ZIP 打包、Host 部署或发布验收。
本功能不使用 AIFLOW，不创建或修改 `.aiflow` 内容。

## 手工体验检查

1. 启动 Standalone，确认第三个“黑白棋”页签显示标准四子、黑方四个合法位置和清晰坐标。
2. 本地双人完成水平、垂直、对角和多方向翻转，确认棋数、回合、最近落子和记录同步。
3. 切换人机三档难度及玩家黑白方，确认玩家执白时电脑先行，电脑回合不能重复点击。
4. 验证提示只高亮建议格；重新开始、模式、颜色和难度切换都清空计时、记录、提示与撤销历史。
5. 分别验证本地单手撤销、人机整轮撤销，以及终局撤销后计时继续且历史耗时不回退。
6. 走到自动跳过和终局，确认连续行动、胜负/平局、最终比分和记录正确。
7. 在浅色、深色主题及较小窗口中确认工具栏、棋盘、提示和记录仍可读且可滚动。
8. 在真实 Host 打开多个黑白棋 Document，确认模式、棋盘、电脑任务、计时和记录互不影响。

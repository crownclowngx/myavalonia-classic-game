# 空当接龙 Document 设计与开发说明

## 功能边界

空当接龙以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.freecell`。每次打开 Document 都创建独立牌局、计时器和后台任务；关闭时取消
牌局生成及提示求解并停止计时。

首版使用一副标准 52 张牌、八个牌列、四个空闲单元和按花色区分的四个基础区。牌按顺序轮流发到八列，前四列各七张、
后四列各六张，全部正面朝上。牌列只能按红黑交替、点数递减连接；基础区从 A 到 K 同花色递增；空闲单元各保存一张牌。
基础区不能主动取回，只有撤销可以恢复动作前状态。四个基础区全部到 K 时获胜。

首版提供编号可解牌局、随机新编号、同局重开、点击与拖放、多步撤销、后台求解提示、计时、步数、安全自动收牌和动画开关。
不提供存档、统计持久化、排行榜、音效、每日挑战、联网、完整解自动播放或 Microsoft 历史编号兼容。

## SOLID 职责与朴素设计

SOLID 是代码评审的首要约束，但不等于为每个类型建立接口。职责按真实变化原因划分：

```text
Features/FreeCell/
├─ Domain/                 # 牌、位置、快照、规则、棋局、求解器和编号供应器
├─ ViewModels/             # 命令、异步取消、计时、选择、提示和动画意图
├─ Views/                  # CardControl、牌桌布局、拖放、代码绘制和动画播放
└─ FreeCellDocument.cs     # Plugin SDK 生命周期适配器
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `FreeCellRules` | 规则预检、容量计算、纯快照提交和安全收牌 | 历史、线程、计时和像素坐标 |
| `FreeCellGame` | 当前快照、原子事务和完整快照撤销 | 求解、随机、命令和 Avalonia |
| `IFreeCellSolver` | 在固定节点预算内给出完整解、无解或超限结果 | 修改真实棋局或显示提示 |
| `IFreeCellDealProvider` | 稳定编号洗牌、候选重试和可解证明 | 页面状态、计时与动画 |
| `FreeCellViewModel` | 后台生成/提示、版本隔离、命令、计时和展示投影 | 复制领域合法性或命中测试 |
| `FreeCellCardControl` | 单张牌面、状态边框和中文辅助名称 | 牌列布局、拖放目标和规则 |
| `FreeCellBoardControl` | 52 个稳定牌控件的布局、输入翻译和动画 | 修改领域集合或自行判断规则 |
| `FreeCellDocument` | Host 标题、初始化、所有权和释放 | 牌局规则与绘制 |

只有后台牌局供应和求解这两个确实需要测试替身的依赖使用窄接口。撤销直接使用完整不可变快照栈，界面沿用 MVVM，
动画计划只是已经提交事务的只读描述。没有引入事件总线、Mediator、State 类层次、仓储、抽象工厂、服务定位器、
跨游戏 CardControl 或通用动画框架。

## 移动容量、自动收牌与撤销

牌列尾部只有形成红黑交替连续降序时才能整体选择。一次批量移动必须等价于借助当前空位逐张完成，容量为：

```text
(空闲单元数 + 1) × 2^可用空列数
```

若目标本身是空列，该列已经被占作最终落点，必须先从可用空列数中扣除。领域预检、真实提交和求解器均调用同一份规则，
避免出现“提示认为可走但界面拒绝”的第二套语义。

安全自动收牌默认开启且可以关闭。A 始终安全；点数大于一的牌仅在两种相反颜色的基础区都至少到达其前一点数时自动收取。
这是充分但保守的条件：系统宁可稍晚收牌，也不会自动移走仍可能承担临时承载作用的牌。新局可以在零步数、无历史状态下
执行安全收牌；运行中开启开关时，只有实际收取了牌才产生一个步骤。

一次玩家移动以及随后产生的全部安全收牌属于同一个领域事务。撤销恢复牌列、空闲单元、基础区、胜负状态和步数，但已经
消耗的时间不回退。非法移动、选择、取消、提示及失败生成均不产生历史。完成后锁定新移动，但仍允许撤销或同局重开。

## 编号牌局与求解器

牌局编号范围为 1 到 2147483647。每个候选使用项目内固定的 SplitMix64 伪随机序列和 Fisher–Yates 洗牌，因此不依赖
`.NET Random` 的版本实现。同一编号从候选零开始按固定顺序尝试，返回首个被实际完整求解的牌组；编号和候选序号共同决定牌序。

求解器使用确定性启发式优先搜索。访问键保存四个基础区，并把空闲单元和八个牌列分别排序以消除规则上对称的位置；优先级鼓励
基础区进展、释放低点数牌和空列，但不删除合法分支。队列耗尽表示已证明无解，节点预算耗尽则明确返回“搜索上限”，两者不能混同。

- 每个生成候选最多扩展 300,000 个状态，最多尝试 32 个候选。
- 当前局面提示最多扩展 1,000,000 个状态，成功时只高亮完整解路径的第一步，不自动执行。
- 生成只接受确实找到胜利路径的候选；全部失败时保留当前棋局，不把“可能可解”冒充“已证明可解”。
- 同局重开复用已经接受的完整牌序，不重复求解；随机新局只是生成并显示一个新的编号。

生成和提示均在后台线程执行。每次移动、撤销、重开、新编号、取消或释放都会取消旧任务并递增棋局版本；后台结果只有在
取消令牌未取消且版本仍匹配时才能写回。生成期间保留当前棋盘但锁定交互，成功后原子替换，失败或取消后重新开放原局。

## CardControl、拖放与动画

`FreeCellBoardControl` 保留 52 个按稳定牌 ID 复用的 `FreeCellCardControl` 子控件。单牌控件用圆角矩形、阴影、系统花色字符和
Light/Dark 调色板绘制，不包含图片、自定义字体或第三方素材；每张牌提供“红桃Q”等中文辅助名称和工具提示。

- 指针移动达到 6 DIP 后进入拖拽，合法目标槽高亮；非法落点在约 120ms 内回弹且不提交领域事务。
- 合法移动约 140ms，级联自动收牌约 120ms，胜利反馈约 250ms；动画默认开启并可关闭。
- 动画播放前领域状态已经提交。控件卸载、主题切换或关闭动画时直接显示最终快照，不回滚半局状态。
- 单击可先选择牌或牌组再点击目标，双击单张顶牌尝试送入对应基础区；局部快捷键为 `Ctrl+Z`、`H` 和 `Esc`。
- 牌桌由 ScrollViewer 承载，长列扩大高度；顶部空闲单元、基础区和整体牌桌均提供中文辅助说明。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 牌组与发牌 | 52 个唯一 ID、四花色 A-K、7/6 分列、编号和候选稳定 |
| 移动规则 | 牌列、空闲单元、基础区、交替降序、空列和容量边界 |
| 自动收牌与撤销 | 安全条件、级联、原子历史、步数恢复、终局和终局撤销 |
| 求解与生成 | 合法胜利路径、确定性、无解、节点超限、取消、候选重试和失败拒绝 |
| ViewModel | 原子替换、失败保留、计时、提示、动画开关、重开、释放和实例隔离 |
| 控件 | 中文辅助名称、牌列命中、6 DIP 阈值、回弹与纯动画阶段 |
| Document 与组合 | 默认/Host 标题、所有权、释放、第十一个注册、稳定 ID 和单向绑定 |
| 文档 | 专项说明、总览链接、SOLID、AIFLOW 与非发布门禁声明 |

测试使用固定编号、脚本求解器、固定牌局供应器和手工 `TimeProvider`；禁止依赖 `Sleep`、墙钟或真实动画帧。

本阶段仅执行：

```powershell
dotnet restore
dotnet build -c Debug -warnaserror --no-restore
dotnet test -c Debug --no-build --no-restore
```

当前不是发布阶段，不配置或运行 Windows CI，不设置覆盖率强制阈值，不执行 Release 构建、ZIP 打包、Host 部署或发布验收。
本功能不使用 AIFLOW，不创建或修改 `.aiflow` 内容。

## 手工体验检查

1. 在 Standalone 打开空当接龙，确认编号 1 完成后台验证后显示八列、四个空闲单元和四个基础区。
2. 输入相同编号两次，确认布局相同；输入非法编号或取消生成，确认当前棋局不被替换。
3. 验证点击、双击、合法拖放、非法回弹、目标高亮、`Ctrl+Z`、`H` 与 `Esc`。
4. 构造空闲单元和空列数量不同的局面，确认批量移动容量及目标空列扣除正确。
5. 开关安全自动收牌，确认级联动画、原子撤销和关闭状态下的手动基础区移动。
6. 完成牌局后确认计时停止、显示胜利层；撤销后重新开放且耗时不倒退。
7. 快速切换编号、取消生成、移动后立即求解或关闭 Document，确认没有旧任务覆盖新状态。
8. 在浅色、深色主题和较小窗口下确认花色、牌面、长列滚动、提示和动画可读。
9. 在真实 Host 打开多个空当接龙 Document，确认编号、棋局、求解、计时和释放互不影响。

# 蜘蛛纸牌 Document 设计与开发说明

## 功能边界

蜘蛛纸牌以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.spider-solitaire`。每次打开 Document 都创建独立对局，关闭后释放计时资源。

首版提供经典三档难度：

| 难度 | 牌组构成 | 同花色每张牌数量 |
| --- | --- | ---: |
| 初级 | 仅黑桃 | 8 |
| 中级 | 黑桃、红桃 | 各 4 |
| 高级 | 四种花色 | 各 2 |

所有难度均使用 104 张牌、10 个牌列、54 张初始牌和 50 张库存牌。初始前四列各 6 张、其余六列各 5 张，
每列只有顶牌正面朝上。库存分五轮发出，每轮向十列各发一张；只要存在空列就禁止发库存。

玩家可以把单张正面牌放到点数大一级的任意花色牌上，也可以移动同花色、连续降序的整段尾部牌组。空列接收
任意合法牌组。牌组移走后自动翻开源列新的顶牌；同花色 K 到 A 出现在牌列顶部时自动收至完成区，完成八组即获胜。

首版包含点击移动、鼠标拖拽、多步撤销、一步提示、同局重开、新洗牌、计时、步数和经典计分。不保存未完成对局，
不提供持久化统计、排行榜、每日挑战、音效、自动求解、可换牌背、触屏专用手势或重做。

## SOLID 职责划分

SOLID 是本功能代码评审的首要约束，但不等于给每个类创建接口。职责按真实变化原因拆分：

```text
Features/SpiderSolitaire/
├─ Domain/                    # 纯规则、牌、快照、洗牌和提示
├─ ViewModels/                # 命令、计时、计分和动画意图
├─ Views/                     # 布局、代码绘制、指针输入和动画播放
└─ SpiderSolitaireDocument.cs # Plugin SDK 生命周期适配器
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `SpiderSolitaireGame` | 发牌、移动、翻牌、收组、快照撤销、提示枚举和胜利判断 | Avalonia、计时、命令和 Host |
| 牌与快照 | 保存稳定牌身份和完整领域状态 | 颜色、坐标、动画进度和命令 |
| `ISpiderCardShuffler` | 返回牌定义的排列 | 修改棋局或判断规则 |
| `SpiderGameTimer` | 基于 `TimeProvider` 累计真实耗时 | UI 调度和胜负判断 |
| `SpiderSolitaireViewModel` | 用户意图、计时、计分投影、命令状态和动画描述 | 指针坐标、命中测试和牌面绘制 |
| `SpiderBoardControl` | 快照布局、代码绘制、点击/拖拽转译和动画播放 | 决定移动是否合法或修改领域集合 |
| `SpiderSolitaireDocument` | Host 标题、初始化、ViewModel 所有权与释放 | 牌局规则和展示属性 |

- **开闭原则：** 蜘蛛纸牌作为扫雷的同级功能域接入，不修改扫雷来容纳纸牌，也不提前建立通用游戏基类。
- **里氏替换：** Document 只遵守普通 `IPluginDocument` 生命周期，不增加 Host 不理解的保存语义。
- **接口隔离：** 只有生产随机洗牌与测试固定洗牌这一真实替换点使用窄接口；计时直接使用 BCL `TimeProvider`。
- **依赖倒置：** 领域引擎依赖洗牌能力而非全局随机数，并再次校验策略结果；领域层不引用 Avalonia 或 Plugin SDK。

设计模式保持朴素：随机与固定洗牌使用 Strategy；撤销直接使用不可变快照栈；界面沿用现有 MVVM。没有引入状态类层次、
事件总线、Mediator、仓储、抽象工厂、服务定位器或通用动画框架。只有未来出现至少两个稳定且真实的共同变化点时，
才评估从扫雷与蜘蛛纸牌抽取共享能力。

## 规则、状态与计分

牌局状态只保留三种：

```text
Ready --首次成功移动/发牌--> Running --完成八组--> Won
  ^              |                ^                  |
  └──同局重开/新局/切难度──────────┘        撤销──────┘
```

“库存耗尽且没有合法移动”只显示无可用移动，不建立不可逆 Lost 状态，因为玩家仍可撤销或重开。

每次成功移动或发牌前保存完整不可变快照。自动翻牌和自动收组是触发动作的一部分；撤销恢复牌列、正反面、库存、
完成组与领域状态。累计操作惩罚和耗时有意不存入快照：经典计分从 500 开始，每次成功移动、发牌或撤销扣 1 分，
每完成一组加 100 分；撤销不应消除玩家已经付出的时间或操作成本。提示、选择、取消和非法操作均不计步。

提示不会修改棋局，也不是求解器。它稳定枚举合法移动，依次优先完成牌组、翻开背面牌、连接同花色、清空源列和其他
移动；无牌列移动时提示库存，并排除把完整一列原样搬到空列的循环动作。同优先级按源列、牌位置和目标列排序，
让行为和测试可重复。

## 数据流与动画设计

一次拖拽的完整数据流如下：

1. `SpiderBoardControl` 在指针移动超过 6 DIP 后进入拖拽并捕获指针；它询问 ViewModel 哪些目标合法，不读取点数规则。
2. 合法松开被转成“源列、起始位置、目标列”意图；ViewModel 把意图交给 `SpiderSolitaireGame`。
3. 游戏引擎在一次同步事务中完成移动、源列翻牌、完成组移除、胜利判断和历史入栈，并返回前后快照。
4. ViewModel 更新计时、计分与摘要，再把前后快照转换为动画阶段描述。
5. View 根据稳定牌 ID 在快照间插值。领域状态此时已经完整提交，因此动画中断、主题切换或 View 卸载时可直接显示最终快照。

动画阶段顺序固定为“移动或发牌 → 翻牌 → 收组 → 胜利”。移动约 140ms、翻牌约 180ms、发牌约 300ms、收组约
400ms、胜利提示约 250ms。播放期间临时锁定玩家操作，避免多个快照过渡交叉。动画计时只属于 View；单元测试验证
纯阶段描述和最终状态，不等待真实渲染帧。

## 零图片视觉与输入

牌桌、库存、完成槽、牌面和牌背全部由 `SpiderBoardControl.Render` 使用 Avalonia `DrawingContext` 绘制：

- 牌面由圆角矩形、边框、阴影、点数字符和系统 `♠ ♥ ♣ ♦` 字符组成。
- 牌背使用代码生成的灰蓝交叉线纹，不包含 PNG、SVG、自定义字体或第三方素材。
- Light/Dark 调色板均由插件自己定义，不依赖 Host 私有颜色键；整体延续扫雷的灰蓝中性风格。
- 牌列使用固定牌宽和不同的正面/背面纵向间距；长列扩大绘制高度并由 ScrollViewer 承载。

点击时先选择合法牌组，再点击目标列；点击原选择取消，点击另一合法牌组替换选择。拖拽使用 6 DIP 阈值，合法目标列
显示高亮；非法松开、Esc 或指针捕获丢失不会改变领域状态。快捷键为 `Ctrl+Z` 撤销、`H` 提示和 `Esc` 取消。

## 测试矩阵与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 牌组与初始发牌 | 三档花色、104 个唯一 ID、54/50 分配、正反面、非法洗牌拒绝 |
| 移动规则 | 单牌、同花色牌组、跨花色压牌、混花牌组拒绝、空列、自动翻牌 |
| 库存与收组 | 空列阻止发牌、五轮库存、一次十张、单列/多列收组、八组胜利 |
| 撤销与计分 | 普通移动、翻牌、发牌、完成组、胜利后撤销、累计扣分、不回退耗时 |
| 提示 | 稳定优先级、循环过滤、库存提示和完全无提示 |
| ViewModel 与输入 | 计时启停、选择/取消、拖拽阈值、命令状态、动画阶段、释放与实例隔离 |
| Document 与组合 | 默认/Host 标题、ViewModel 所有权、双 Document 注册、稳定 ID 和单向绑定 |

测试固定牌序并使用手工 `TimeProvider`；禁止依赖随机结果、`Sleep`、墙钟或真实动画耗时。

本阶段仅执行：

```powershell
dotnet restore
dotnet build -c Debug -warnaserror --no-restore
dotnet test -c Debug --no-build --no-restore
```

当前不是发布阶段，不配置或运行 Windows CI，不设置覆盖率强制阈值，不执行 Release 构建、ZIP 打包、Host 部署或
发布验收。上述门禁只在用户明确进入发布阶段后按 `deployment-and-release.md` 执行。本功能也不使用 AIFLOW，
不会创建或修改 `.aiflow` 内容。

## 手工体验检查

1. 在 Standalone 两个标签页间切换，确认扫雷不受影响，蜘蛛纸牌初始为 1 花色且牌列、库存和完成槽清晰。
2. 切换 1/2/4 花色，确认花色构成、状态、计时、步数和分数全部重置。
3. 验证点击选择、再次点击取消、点击目标移动、拖拽合法牌组、非法落点和 Esc 取消。
4. 清空一列后确认库存拒绝发牌；填回空列后确认一次向十列发牌且只计一步。
5. 验证自动翻牌、同花色 K 到 A 自动收组、完成多组和胜利提示。
6. 连续撤销普通移动、发牌、翻牌和收组，确认棋局恢复但耗时与撤销扣分不回退。
7. 验证提示优先高价值移动，`Ctrl+Z` 与 `H` 可用，同局重开恢复原牌序，新游戏重新洗牌。
8. 在浅色、深色主题和不同窗口尺寸下确认牌面、花色、牌背、滚动和动画保持可读。
9. 在真实 Host 中打开多个扫雷和蜘蛛纸牌 Document，确认标题、棋局、计时、历史与难度互不影响。

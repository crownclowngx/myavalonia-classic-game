# 数独 Document 设计与开发说明

## 功能边界与经典规则

数独以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.sudoku`。每次打开 Document 都创建独立对局、计时器和题目生成生命周期；关闭时停止刷新并取消仍在运行的生成任务。

首版固定为经典 9×9 棋盘和 3×3 九宫格。每一行、每一列、每一宫最终都必须恰好包含 1–9。默认使用简单题，提供简单、
中等、困难三个休闲档位：

| 难度 | 给定数字范围 | 内置题数 |
| --- | ---: | ---: |
| 简单 | 40–45 | 8 |
| 中等 | 33–39 | 8 |
| 困难 | 26–32 | 8 |

难度只按给定数字数量分档，不宣称等价于专业赛事使用的解题技巧评级。24 道内置题都由自动化测试确认题面合法、给定数字与答案一致且只有一个解。

输入采用柔性校验：玩家数字会立即保留；只有同行、同列或同宫出现重复时才同时高亮冲突格，不对照答案累计错误次数，也没有“三次错误结束”。
填满且逐格匹配唯一答案后完成游戏并停止计时。

首版包含候选笔记、清除、单步撤销、提示、重开、题库新局和运行时生成。不提供重做、暂停、自动候选、存档、统计、排行榜、
联网题库、音效和非 9×9 变体。

## SOLID 职责与朴素设计

数独与其他小游戏平级，不修改现有领域，也不抽取跨游戏棋盘框架：

```text
Features/Sudoku/
├─ Domain/                  # 纯规则、求解、题源和单局状态
├─ ViewModels/              # 页面投影、计时、异步编排和动画计划
├─ Views/                   # AXAML、零图片棋盘、局部输入和动画回放
└─ SudokuDocument.cs        # Plugin SDK 标题、所有权与释放适配
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `SudokuRules` | 坐标、同伴关系、候选、冲突和完成判定 | 随机、对局提交、UI |
| `SudokuSolver` | 最少候选优先回溯、首次求解和有限解计数 | 题目分档、玩家状态、线程调度 |
| `ISudokuPuzzleProvider` | 提供题库题目和可取消生成入口 | 修改当前对局或 ViewModel |
| `SudokuPuzzleProvider` | 24 道题库、随机终盘、挖空和唯一解门禁 | 玩家命令、动画和 Plugin SDK |
| `SudokuGame` | 数字、笔记、提示、完成状态和撤销快照的原子提交 | 求解、随机、计时和文案 |
| `SudokuViewModel` | 选择、命令、计时、异步生成、投影和动画通知 | 重复实现冲突、求解或绘制 |
| `SudokuAnimationPlan` | 固定阶段、目标格、持续时间和纯进度函数 | 创建计时器、控件或领域回滚 |
| `SudokuBoardControl` | 绘制、命中测试、局部键位映射和视觉回放 | 判题、提示答案或生成题目 |
| `SudokuDocument` | Host 标题、ViewModel 所有权和级联释放 | 棋盘规则与玩家操作 |

- **单一职责：** 规则、求解、题源、可变对局、页面投影、绘制和 Host 生命周期按真实变化原因拆分。
- **开闭原则：** ViewModel 依赖窄题源接口；未来替换题库或生成算法无需修改对局规则。
- **里氏替换：** `SudokuDocument` 遵守普通 `IPluginDocument` 语义，不伪装成可持久化 Document。
- **接口隔离：** 只为生产题源与确定测试确实需要替换的边界建立接口，不为空洞规则类创建接口层次。
- **依赖倒置：** ViewModel 不依赖 `Random.Shared` 或具体回溯实现；生成器接受可控随机源，测试可精确复现。

唯一使用的结构性模式是朴素 Strategy：`ISudokuPuzzleProvider` 隔离题目供应。撤销采用完整的 81 格轻量 Memento 快照，避免为
同行、同列、同宫的候选自动清理维护脆弱逆操作。不引入事件总线、Mediator、仓储、跨游戏基类或状态类层次。

## 题库、生成与原子替换

内置题库同步返回，保证打开 Document 和切换难度没有等待。相同难度的“新游戏”会排除当前题目，避免立即重复；“重新开始”保留原题，
清除玩家数字、笔记、提示、历史和计时。

“生成题目”在后台线程执行：

1. 使用随机化回溯创建一个完整无冲突终盘。
2. 打乱 81 个位置并依次尝试挖空。
3. 每次挖空后通过求解器计数，计到两个解即提前停止；只有仍为唯一解才保留本次挖空。
4. 达到所选难度的给定数字范围后返回完整 `SudokuPuzzle`；最多尝试 10 个终盘。
5. ViewModel 只在完整题目成功返回后一次替换当前对局。异常、达到尝试上限或取消时保留当前题目和生成期间的新进度。

生成期间当前棋盘仍可操作，只禁用重复生成、难度切换和题库新局，并提供明确的取消按钮。Document 释放会取消生成，避免关闭标签后留下工作任务。

## 对局、计时与输入语义

- 给定格和提示格不可直接修改；提示优先填入选中的可编辑空格，否则选择按行优先的首个空格。
- 普通填数会清空本格笔记，并从同行、同列、同宫自动移除相同候选；撤销恢复操作前完整快照。
- 笔记模式只在空白可编辑格切换 1–9；清除只影响普通玩家数字，不自行恢复以前自动移除的候选。
- 每次成功填数、清除、笔记切换或提示都可撤销；不提供重做。撤销完成步骤会重新开放棋盘并继续累计原有用时。
- 计时从首次有效操作开始，完成时冻结；重开、新局和难度切换归零。
- 单击格子选择；方向键在边界内移动选择；主键盘和数字键盘 1–9 输入，0、Backspace、Delete 清除，N 切换笔记。
- 快捷键只由获得焦点的数独棋盘处理，无关按键继续交给 Host；数字按钮和所有主要操作都有鼠标入口。

## UI 与简单动画

棋盘由 `SudokuBoardControl` 使用 Avalonia DrawingContext 零图片绘制。细线区分普通格，粗线分隔九宫格；给定、玩家和提示数字采用不同颜色，
候选数字按 3×3 小网格排列。选中格突出同行、同列、同宫和相同数字；浅色、深色主题均使用插件自有资源，小窗口由外层滚动区域承载。

每个格子投影都生成包含行列、数字来源、候选和冲突的中文无障碍说明，棋盘悬停提示复用该说明。

动画默认开启，只属于当前 Document，可随时关闭：

- 填数或提示数字从 0.85 缩放到 1，持续 120ms；
- 有冲突时相关格轻微水平衰减抖动，持续 180ms；
- 完成后九个宫依次出现短波纹，总计 450ms。

动画计划只提供纯进度，BoardControl 使用约 16ms 的 DispatcherTimer 重绘。新反馈会替换旧反馈，不阻塞玩家输入或延迟领域提交；关闭动画、
更换 DataContext 或离开视觉树时立即停止计时器并清空视觉状态。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 规则 | 坐标、同伴、候选、行/列/宫冲突双方、完成判定、非法盘面 |
| 求解 | 正确答案、无解、多解计数上限、取消、唯一解 |
| 题源 | 每档 8 题、提示数范围、防立即重复、三级随机生成、给定与答案一致 |
| 对局 | 给定保护、柔性填数、清除、笔记切换与自动清理、提示锁定、快照撤销、完成后撤销、重开 |
| ViewModel | 默认局、难度切换、新局、计时、动画开关、生成成功/失败/取消、进度保留、释放、多实例隔离 |
| View | 四角/中心命中、数字/清除/N/方向键映射、无关按键、动画中断清理、中文辅助说明 |
| 插件组合 | 第七个普通 Document、稳定 ID、描述分类、包装单向绑定、Standalone 编译与释放 |

当前开发阶段只执行：

```powershell
dotnet restore
dotnet build -c Debug -warnaserror --no-restore
dotnet test -c Debug --no-build --no-restore
```

本功能不使用 AIFLOW，不创建或修改 `.aiflow` 内容。当前不是发布阶段，不创建或运行 Windows CI，不设置覆盖率阈值，
不执行 Release 构建、ZIP 打包、Host 部署或发布验收。

## 手工体验检查

1. 启动 Standalone 第七个“数独”页签，确认默认简单题、9×9/3×3 边界、来源和零秒计时清晰可见。
2. 用点击和方向键选择四角及中心格，分别用主键盘、数字键盘和侧边数字按钮输入；确认无关按键未被吞掉。
3. 输入同行、同列和同宫重复数字，确认输入仍被保留且所有冲突方同时高亮；清除后高亮消失。
4. 开启候选笔记并录入多个数字，再填入一个正式数字，确认本格笔记及同伴中的相同候选被清理；撤销后完整恢复。
5. 使用提示，确认优先填入选中空格、颜色区别于给定数字且不可直接清除；撤销后恢复为空格。
6. 验证首次有效操作开始计时，重开保留题目并归零，新游戏避免立即重复，难度切换使用对应题库。
7. 分别生成简单、中等、困难题；生成期间继续操作当前局，取消或模拟失败时确认进度保留，成功时确认原子替换。
8. 完成最后一格，确认计时停止、棋盘锁定和九宫格波纹；撤销后重新开放并继续计时。
9. 观察填数缩放和冲突抖动；播放中关闭动画或切换页签，确认没有残留动画、后台刷新或锁死输入。
10. 使用浅色、深色主题和较小窗口检查文字、候选、冲突、按钮与滚动；在真实 Host 打开多个数独 Document，确认状态互不影响。

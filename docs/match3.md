# 消消乐 Document 设计与开发说明

## 功能边界与固定规则

消消乐以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.match3`。每次打开 Document 都创建一局独立游戏；首版固定使用 8×8 棋盘、
六种棋子、30 步和 1500 分目标，不提供撤销、存档、排行榜、音效、道具、关卡或自定义参数。

新局棋盘没有现成三连且至少存在一步合法交换。玩家可以依次点击两个相邻棋子，也可以从一个格子拖到正交相邻格；普通
交换只有在产生匹配时才成立，两个特殊棋子互换以及彩虹球与任意棋子互换可以直接成立。无效交换不扣步、不计分，界面只
播放交换后换回的反馈。

一次有效交换只扣一步。领域层会完整完成当前匹配、特殊连锁、重力、补位和后续连锁，再统一结算：每个计分格基础 10 分，
乘以从 1 开始的连锁层级；同一波中同一格只计一次。回合结束时先判断是否达到 1500 分，再判断步数是否耗尽，因此最后一步
达标仍然胜利。稳定棋盘若没有合法交换，会免费生成一张新的普通棋盘；不保留旧棋子或特殊能力。

## 特殊棋子和组合

- 四个同色棋子直线匹配时生成同方向的行消或列消棋子。
- 五个及以上同色棋子直线匹配时生成彩虹球；彩虹球没有普通颜色，也不参与普通匹配。
- 同一连通匹配同时包含横向和纵向三连时生成范围炸弹，单独触发清除中心 3×3。
- 冲突优先级固定为彩虹球、范围炸弹、行列消。玩家交换形成的特殊棋子优先落在目标格，其次源格；自然连锁使用交叉点或直线中央格。
- 新生成的特殊棋子在当前波保留；既有特殊棋子被消除时递归展开效果，每波每枚特殊棋子最多触发一次。
- 彩虹球被其他爆炸间接命中时清除当前数量最多的普通颜色，数量相同按颜色枚举顺序裁决。

| 组合 | 固定效果 |
| --- | --- |
| 行消 + 行消 | 清除两枚棋子所在的两行 |
| 列消 + 列消 | 清除两枚棋子所在的两列 |
| 行消 + 列消 | 从交换目标清除一整行和一整列 |
| 行/列消 + 范围炸弹 | 从交换目标清除相邻三行和三列 |
| 范围炸弹 + 范围炸弹 | 清除交换目标中心 5×5 |
| 彩虹球 + 普通棋子 | 清除该颜色全部棋子 |
| 彩虹球 + 行/列消 | 把该颜色棋子交替转换为行消、列消并触发 |
| 彩虹球 + 范围炸弹 | 把该颜色棋子转换为范围炸弹并触发 |
| 彩虹球 + 彩虹球 | 清除整个棋盘 |

## SOLID 职责与朴素设计

```text
Features/Match3/
├─ Domain/       # 纯规则、生成器、整回合解析、状态和不可变 Transition
├─ ViewModels/   # 页面状态、选择、提示、命令和纯动画时间线
├─ Views/        # AXAML、原生图形绘制、命中测试与视觉回放
└─ Match3Document.cs
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `Match3Rules` | 匹配、相邻交换、合法行动和棋盘校验 | 随机、分数、动画和 UI |
| `Match3BoardGenerator` | 生成稳定且可行动的普通棋盘 | 对局提交和特殊组合 |
| `Match3TurnResolver` | 在副本中完成消除、特殊展开、重力、补位与连锁 | 持有真实步数或绘制 |
| `Match3Game` | 原子提交棋盘、分数、步数和胜负 | 选择、提示外观和计时器 |
| `IMatch3RandomSource` | 隔离唯一需要替换的随机能力 | 修改棋盘或决定规则 |
| `Match3AnimationPlan` | 把 Transition 映射成固定时长阶段 | 调度线程或修改领域状态 |
| `Match3ViewModel` | 编排设备无关输入、提示、文案和动画生命周期 | 重新计算匹配和计分 |
| `Match3BoardControl` | 原生绘制、点击/拖动命中和视觉回放 | 判定合法交换或特殊效果 |
| `Match3Document` | Host 标题与独立 ViewModel 所有权 | 持久化和虚假资源释放 |

只使用了随机 Strategy 和不可变 Transition 两个直接解决问题的模式。没有跨游戏基类、事件总线、Mediator、仓储、状态类
层次或工厂体系。领域类型保持插件内部，公共面仅包含 Host/Avalonia 构造所需的 Document、ViewModel 和控件。

## 原子回合与失败边界

1. ViewModel 把已验证的相邻位置交给 `Match3Game`。
2. Resolver 复制棋盘，在副本中交换并识别普通匹配或特殊组合。
3. 每波先确定特殊生成锚点，再展开既有特殊效果，记录计分集合并执行重力和随机补位。
4. 最多允许 64 层连锁；随机源返回范围外值、抛出异常或超过上限时直接失败，真实棋盘、分数和步数均保持原值。
5. 候选棋盘稳定后检查合法行动；无解则使用有界生成器重建。生成器随机尝试 256 次后使用已知可行动模板，保证不会死循环。
6. 完整结果成功后，Game 一次覆盖棋盘、分数、步数和状态，并把只读 Transition 交给 View 回放。

## UI、输入与动画

- 六种棋子同时使用不同颜色和不同轮廓：圆形、圆角方形、菱形、三角形、六边形和带内环珍珠；不能只依赖颜色区分。
- 特殊棋子叠加横线、竖线、范围圆标记或多色圆环，并为棋盘及悬停格提供中文可访问说明。
- 指针按下时捕获，释放到正交相邻格执行拖动交换；释放回原格或非相邻位置按普通点击处理。
- “提示”确定性高亮第一组合法交换，直到下一次输入或棋盘变化；没有闲置计时器。
- 动画默认开启：交换 120ms、无效换回 120ms、每波消除 140ms、下落补位 160ms、洗牌 220ms。
- 动画期间锁定输入且不缓存操作。关闭动画、重新开始、切换 DataContext 或离开视觉树时停止视觉计时器并立即显示已提交结果。
- 页面提供当前分数/目标、剩余步数、状态、“重新开始”“提示”和“动画效果”，支持浅色/深色主题及小窗口滚动。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 生成与规则 | 六种棋子、无初始匹配、至少一步、病态随机后备、横纵匹配、彩虹隔离、相邻校验 |
| 特殊生成 | 四连、五连、T/L、优先级、交换锚点和自然锚点 |
| 特殊组合 | 两种同行列组合、交叉、行列加范围、双范围、彩虹加普通/行列/范围/彩虹 |
| 回合事务 | 无效换回、一步只扣一次、计分层级、胜负顺序、异常原子回滚、新局与多实例隔离 |
| ViewModel/动画 | 点击、拖动、提示清理、输入锁、开关取消、固定阶段与时长 |
| Document/组合 | 默认和 Host 标题、无虚假持久化/释放、第十二个注册、稳定 ID、包装绑定、Standalone 页签 |

开发阶段执行：

```powershell
dotnet restore --locked-mode
dotnet build ClassicGamePlugin.slnx -c Debug -warnaserror --no-restore
dotnet test tests/ClassicGamePlugin.Tests/ClassicGamePlugin.Tests.csproj -c Debug --no-build --no-restore
```

要求零错误、零警告、零失败、零跳过。本功能不使用 AIFLOW，不创建或修改 `.aiflow` 内容；当前不是发布阶段，不新增覆盖率
阈值，不运行 Windows CI/Smoke、Release 构建、Managed Plugin ZIP、Host 部署或发布门禁。

## 手工体验检查

1. 在 Standalone 第十二个“消消乐”页签确认 8×8 棋盘、30 步、1500 分目标且开局没有现成匹配。
2. 分别用两次点击和拖动交换；确认无效交换换回且不扣步，有效交换完整落定后只扣一步。
3. 制造四连、五连、T/L，并逐项检查九类组合的范围、递归触发和计分。
4. 连续触发多层补位匹配，确认动画按消除与下落阶段播放且界面不接受中途输入。
5. 点击“提示”确认两格持续高亮；下一次选择、拖动、重开或棋盘变化后高亮消失。
6. 播放中关闭动画，确认立即落定；重新开启后后续回合恢复动画。
7. 达到 1500 分确认胜利，最后一步未达标确认失败，重开恢复零分和 30 步。
8. 在浅色、深色主题和较小窗口下确认颜色、轮廓、特殊标记、文字和滚动清晰可用。
9. 在真实 Host 打开多个消消乐 Document，确认棋盘、分数、步数、提示和动画开关互不影响。

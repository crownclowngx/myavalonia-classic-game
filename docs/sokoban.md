# 推箱子 Document 设计与开发说明

## 功能边界与规则口径

推箱子以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.sokoban`。每次打开 Document 都创建独立棋局；十二张内置地图全部可以直接选择，
完成记录和当前进度不跨 Document 或应用重启保存。

- 玩家可以走到相邻地面或目标点；墙会阻挡玩家。
- 玩家只能沿移动方向推动一个箱子，箱子后方是墙或另一个箱子时移动无效；不能拉箱子。
- 箱子和目标属于两层状态，箱子可以进入和离开目标点；所有箱子同时位于目标点时完成本关。
- 完成后锁定方向移动，但允许撤销、重开和切关。系统不自动跳关。
- 箱子进入非目标死角仍是合法推动，不检测、不阻止也不自动提示，玩家通过不限次数撤销或重开恢复。
- 每个有效移动可撤销一次，普通行走和推动采用相同的单步语义；无效移动不产生历史。首版不提供 Redo。
- 不包含地图导入、编辑器、自动求解、提示、计时、排行榜、音效、联网或持久化。

## 地图系统与可解性

`SokobanLevelParser` 读取行宽一致、边界完全封闭的矩形文本地图：

| 字符 | 含义 |
| --- | --- |
| `#` | 墙 |
| 空格 | 普通地面 |
| `.` | 目标点 |
| `$` | 普通地面上的箱子 |
| `@` | 普通地面上的玩家 |
| `*` | 目标点上的箱子 |
| `+` | 目标点上的玩家 |

解析阶段验证最小尺寸、矩形行宽、封闭墙边界、合法字符、唯一玩家、至少一个箱子，以及箱子数等于目标数；异常使用中文说明
具体原因。解析器不承担求解职责，避免把运行时复杂度引入一个固定内置目录。测试为每张地图保存已知方向序列并通过真实
`SokobanGame` 回放到完成状态，从而同时验证目录顺序、地图可解性和领域规则。

十二关使用稳定英文 ID，中文名称只负责展示。前四关为“入门”，中间四关为“进阶”，最后四关为“挑战”；关卡全部解锁，
上一关、下一关和下拉选择都会立即创建该关的新棋局并清空旧历史，不弹出确认框。

## SOLID 职责与朴素设计

```text
Features/Sokoban/
├─ Domain/                 # 地图解析、内置目录、不可变快照和纯游戏规则
├─ ViewModels/             # 关卡命令、展示投影、输入缓存和纯动画计划
├─ Views/                  # AXAML、专用 DrawingContext 棋盘和局部键盘输入
└─ SokobanDocument.cs      # Plugin SDK 生命周期适配器
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `SokobanLevelParser` | 文本语法与结构校验 | 求解、保存和 UI |
| `SokobanLevelCatalog` | 十二关的稳定顺序与元数据 | 当前进度和解锁状态 |
| `SokobanLevelDefinition` | 只读静态地形与初始对象 | 一局中的移动 |
| `SokobanGame` | 原子移动、推动、完成和快照恢复 | 关卡选择、键盘和动画 |
| `SokobanGameSnapshot` | 隔离保存玩家、箱子、计数和完成状态 | 修改真实棋局 |
| `SokobanViewModel` | 命令、切关、状态投影与动画输入编排 | 重复实现墙和推动规则 |
| `SokobanAnimationPlan` | 纯时间进度和曲线 | Avalonia 计时器与领域提交 |
| `SokobanBoardControl` | 绘制、焦点、键盘映射和短时回放 | 判断移动是否合法 |
| `SokobanDocument` | Host 标题和独立 ViewModel 所有权 | 游戏规则与视觉资源 |

只读关卡列表直接注入 ViewModel，不为唯一内置目录增加仓储或工厂接口。Undo 使用完整不可变快照栈，不建立 Memento 类层次；
游戏之间不抽取通用棋盘框架，也不引入事件总线、Mediator、State 或抽象工厂。非直观实现使用中文 XML 注释解释状态所有权、
原子提交和取消顺序，简单属性避免重复代码表面的空洞注释。

## 移动事务、撤销与动画

一次方向输入按以下顺序处理：

1. 完成状态直接拒绝；计算相邻格，墙体直接拒绝。
2. 相邻格存在箱子时再检查箱子后方；墙或箱子阻挡时整步拒绝。
3. 创建走前完整快照；合法推动先移动箱子，再更新玩家、移动数、推动数和完成状态。
4. 压入快照历史并返回包含走前、走后、箱子起止位置的移动结果。
5. ViewModel 立即发布新的领域摘要；动画开启且 View 已订阅时，使用移动结果进行视觉回放。

玩家与箱子使用 120ms 三次减速滑动；最后一个箱子归位后追加 360ms 目标脉冲。动画期间只覆盖保存最后一个方向，回放结束后再
提交该方向，避免长队列导致画面落后。Undo、重开和切关先清除缓存输入并取消视觉回放，再恢复目标状态；关闭动画属于显示偏好，
会落定当前移动并无动画执行最后缓存方向。

`DispatcherTimer` 只存在于已经挂载且正在播放的棋盘控件中，约 16ms 刷新一次。切换 Game、离开视觉树或收到取消请求时立即
停止计时器并清理计划；领域状态早已原子提交，因此取消不会产生半格玩家或半次推动。

## UI 与键盘控制

- 专用控件使用 Avalonia DrawingContext 零图片绘制地面、墙、目标、箱子和玩家，按地图宽高计算最大可用单元格并居中。
- 工具区提供十二关选择、上一关、下一关、重开、撤销与动画开关；状态区显示难度、移动数、推动数和归位进度。
- 单击棋盘后，方向键与 W/A/S/D 移动，U 或 Ctrl+Z 撤销，R 重开。只有获得焦点的棋盘处理这些按键，无关按键继续交给 Host。
- 四个方向、撤销、重开和切关都有鼠标入口。格子悬停提示提供行列、墙、目标、箱子或玩家的中文说明，棋盘公开整体辅助名称。
- 页面使用插件自有 Light/Dark 资源，小窗口由外层滚动区域承载；墙体、箱子和玩家在两种主题下保持足够对比。

## 自动化测试与开发门禁

| 范围 | 必测场景 |
| --- | --- |
| 解析与目录 | 七种字符、矩形、边界、非法字符、玩家/箱子/目标数量、稳定 ID、难度顺序 |
| 地图可解性 | 十二关逐一通过已知答案回放完成 |
| 领域规则 | 普通移动、撞墙、单箱推动、墙后/箱后拒绝、目标覆盖、死角合法、完成锁定 |
| 快照与撤销 | 无效零副作用、连续 Undo、推动恢复、完成恢复、重开和多实例隔离 |
| ViewModel | 默认关、全关选择、上下关边界、切关清历史、动画开关、最后方向覆盖和取消顺序 |
| View 与动画 | 120ms/360ms 进度、键位与修饰键、无关按键、命中、中文辅助说明和卸载清理 |
| 插件组合 | 第八个普通 Document、稳定 ID、描述分类、包装单向绑定和 Standalone 编译 |

当前开发阶段只执行：

```powershell
dotnet restore
dotnet build -c Debug -warnaserror --no-restore
dotnet test -c Debug --no-build --no-restore
```

本功能不使用 AIFLOW，不读取、创建或修改 `.aiflow` 内容。当前不是发布阶段，不增加或运行 Windows CI、Release 构建、ZIP
打包、Host 部署、发布验收或覆盖率阈值。

## 手工体验检查

1. 启动 Standalone 第八个“推箱子”页签，确认默认第一关、墙、目标、箱子、玩家和三个计数清晰可见。
2. 逐一选择十二关，确认入门、进阶、挑战顺序正确，切关立即清空移动、推动和撤销历史。
3. 单击棋盘后分别使用方向键和 W/A/S/D；确认撞墙、推墙后箱子、推两个箱子都不改变计数。
4. 使用方向按钮、U、Ctrl+Z 和撤销按钮验证普通行走、推动、连续撤销及完成后撤销。
5. 将箱子推进非目标死角，确认系统允许操作且可通过撤销或重开恢复。
6. 快速连续输入多个方向，确认动画期间只执行最后方向；播放中撤销、重开或切关没有残留动画。
7. 关闭动画后快速移动，确认状态立即落定；重新开启后观察 120ms 滑动和完成时 360ms 目标脉冲。
8. 使用浅色、深色和较小窗口检查对比、滚动与布局；在真实 Host 打开多个推箱子 Document，确认关卡和历史互不影响。

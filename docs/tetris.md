# 俄罗斯方块 Document 设计与开发说明

## 功能边界与现代规则

俄罗斯方块以普通、不可持久化的 `IPluginDocument` 接入 Host，稳定身份为
`myavalonia.plugin.classic.game.document.tetris`。每次打开 Document 都立即创建一局独立游戏；棋盘、分数、最高分、动画偏好和
未完成对局均不跨 Document 或应用重启保存。首版不提供联网、排行榜、音效、触控手势、自定义键位或 180° 旋转。

- 棋盘包含 10×20 可见区域和顶部 4 行隐藏生成区。方块生成受阻，或一次锁定和消行完成后隐藏区仍有固定方块时结束游戏。
- 随机队列使用 7-bag：每袋七种方块各一次并独立洗牌；界面始终绘制后续 5 枚方块。
- 暂存区初始为空。每枚活动方块最多暂存一次；首次暂存消耗队首，后续交换不消耗队列，换入方块恢复生成位置和朝向。
- 幽灵块显示活动方块的最低合法落点，只作为半透明视觉提示，不进入棋盘或碰撞状态。
- 旋转使用完整 SRS：`0/R/2/L` 四个朝向，JLSTZ 和 I 使用各自五级踢墙表，O 不位移；支持顺、逆时针。
- 接地后启动 500ms 锁定延迟。接地状态下成功移动或旋转最多重置 15 次；硬降立即锁定，软降撞底仍等待锁定延迟。
- 等级从 1 开始，每 10 行提升一级。单格重力周期为
  `max(16ms, (0.8 - (等级-1)×0.007)^(等级-1) 秒)`，软降周期为当前重力周期的 1/20。

## 计分口径

以下分值均乘以消行前的当前等级：

| 行为 | 基础分 |
| --- | ---: |
| 普通单消 / 双消 / 三消 / 四消 | 100 / 300 / 500 / 800 |
| T-Spin Mini 0 / 1 / 2 行 | 100 / 200 / 400 |
| T-Spin Full 0 / 1 / 2 / 3 行 | 400 / 800 / 1200 / 1600 |
| Perfect Clear 1 / 2 / 3 / 4 行 | 800 / 1200 / 1800 / 2000 |
| Back-to-Back 四消 Perfect Clear | 3200，替代普通四消全清奖励 |

软降每格 1 分，硬降每格 2 分。连续两次以上有消行的锁定从第二次开始增加
`50 × Combo 序号 × 等级`；未消行即清空 Combo。四消和带消行的 T-Spin 属于困难消行，连续困难消行从第二次起把基础消行分
乘以 1.5；普通消行中断 Back-to-Back，未消行锁定保留链。

T-Spin 要求最后一次横向操作为成功旋转，并且 T 中心四角至少三处被固定方块占用或越界。两个朝前角都被占用时判 Full，
否则判 Mini；若旋转使用 SRS 第五个踢墙测试，则 Mini 升级为 Full。重力、软降和硬降不会清除最后旋转标记，水平移动、暂存、
锁定和生成新方块会清除。

## SOLID 职责与朴素设计

```text
Features/Tetris/
├─ Domain/                 # 方块几何、SRS、7-bag、权威对局与确定性 Game Loop
├─ ViewModels/             # 命令、状态投影和纯动画计划
├─ Views/                  # AXAML、局部按键、自定义绘制与视觉计时器
└─ TetrisDocument.cs       # Plugin SDK 标题和 ViewModel 所有权适配
```

| 组件 | 单一职责 | 明确不负责 |
| --- | --- | --- |
| `TetrisRules` | 七种方块坐标、四朝向和完整 SRS 踢墙表 | 棋盘提交、随机、计时、UI |
| `ITetrominoSource` | 按次提供下一种方块 | 棋盘、预览展示和分数 |
| `SevenBagTetrominoSource` | Fisher-Yates 洗牌和逐袋输出 | 暂存、生成碰撞和测试造局 |
| `TetrisGame` | 原子移动、旋转、暂存、锁定、消行、计分和终局 | 真实时间、键盘、动画和 Plugin SDK |
| `TetrisGameLoop` | 把时间增量转换为重力与锁定事务 | 读取系统时钟、绘制和计分公式 |
| `TetrisAnimationPlan` | 90ms 硬降与 160ms 消行的纯进度 | 创建计时器或回滚领域状态 |
| `TetrisViewModel` | 命令、摘要投影、暂停和动画编排 | 重复实现 SRS、碰撞或计分 |
| `TetrisBoardControl` | DrawingContext 绘制、局部按键、DAS/ARR 与视觉计时 | 决定合法移动或修改固定棋盘 |
| `TetrisDocument` | Host 标题和独立 ViewModel 所有权 | 游戏循环和虚假资源释放 |

唯一使用的设计模式是方块来源的 Strategy。时间循环是普通协调对象，动画计划是只读数据；没有事件总线、Mediator、State
类层次、仓储、抽象工厂或跨游戏棋盘基类。这样保留 SOLID 的真实变化边界，同时不为只有一个实现的规则制造接口。

## 事务、Game Loop 与动画

`TetrisBoardControl` 挂载后用约 16ms 的 `DispatcherTimer` 和单调 `Stopwatch` 计算实际时间差，再把时间差传给
`TetrisGameLoop.Advance`。循环自身不读取时钟，因此单元测试可直接推进 499ms、1ms 或一个大时间片，并验证完全相同的结果。

一次锁定按以下顺序原子执行：

1. 在写入活动方块前，根据最后旋转及四角占位判断 T-Spin。
2. 把四个格子写入候选棋盘，找出全部满行并一次压缩。
3. 计算普通/T-Spin、Combo、Back-to-Back、Perfect Clear 和等级倍率。
4. 提交分数、总行数、固定棋盘、暂存权限与下一枚方块；生成受阻或隐藏区残留时进入终局。
5. 返回隔离的前后棋盘、锁定方块、硬降起点和消除行，供 View 回放，动画不能修改真实状态。

动画默认开启且可以在每个 Document 内关闭。重力阶段按循环累计进度平滑绘制，但碰撞仍使用整数格；硬降用 90ms 三次减速
轨迹，消行用 160ms 闪烁和向下收拢。播放期间暂停循环并忽略移动输入。关闭动画、重开、暂停、隐藏、卸载或顶层窗口失活时
立即取消临时视觉并显示已经提交的最终状态，不保留按键、DispatcherTimer 或半完成事务。

## UI 与输入

- 棋盘、固定方块、活动方块、幽灵块、暂存和五个预览均由专用控件零图片绘制；浅色和深色主题使用插件自有资源。
- 单击棋盘获得焦点后，左右或 A/D 移动，下或 S 软降，上或 X 顺时针，Z 逆时针，Space 硬降，C/Shift 暂存，P 暂停。
- 水平持续按键由控件实现 150ms DAS 和 40ms ARR；左右同时按下时使用最后按下方向，松开后重新计算有效方向。
- 无关按键和带修饰组合键不被游戏吞掉。全部主要操作同时提供按钮，状态区显示分数、等级、消行、Combo 和 B2B。
- 普通按钮获得焦点不会暂停；棋盘不可见、脱离视觉树或顶层窗口失活才自动暂停。恢复必须由玩家点击“继续”或按 P。

当前开发阶段只执行：

```powershell
dotnet restore
dotnet build -c Debug -warnaserror --no-restore
dotnet test -c Debug --no-build --no-restore
```

本功能不使用、读取或修改 AIFLOW 内容。当前不是发布阶段，不增加或运行 Windows CI、Release 构建、ZIP 打包、Host 部署、
发布验收或覆盖率阈值。

## 手工体验检查

1. 启动 Standalone 第九个“俄罗斯方块”页签，确认新局立即开始，暂存为空且右侧恰有五枚预览。
2. 验证方向键与 A/D/S、X/Z、Space、C/Shift、P，并确认按钮入口行为一致、无关组合键仍交给 Host。
3. 将方块靠墙、靠堆叠旋转，确认 SRS 踢墙可用；完全无空间时旋转不移动方块。
4. 验证暂存每枚只能一次、换入恢复生成朝向、幽灵块与硬降落点一致。
5. 分别完成单至四消、T-Spin、连续消行、Back-to-Back 和全清，核对分数、Combo、B2B、等级与速度。
6. 接地后移动或旋转，确认存在短暂操作余量；持续操作最终仍会因 15 次上限锁定。
7. 观察平滑自然下降、90ms 硬降和 160ms 消行；播放中关闭动画应立即落定且继续正常计时。
8. 切换页签、最小化或切出窗口，确认游戏自动暂停且没有后台下落；返回后由玩家明确继续。
9. 使用浅色、深色和较小窗口检查方块辨识、滚动、状态文字及两侧预览；在真实 Host 打开多个 Document 验证完全隔离。
